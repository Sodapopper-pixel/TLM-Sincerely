# 探针式任务可行性检测 + 攻击优先抢占

## 方案概述

当女仆当前任务空闲时，不依赖外部 API 预判——直接快速切换候选任务让 brain 执行一轮搜索，从 brain 内存读取结果。**找到有活 → 停留；全无活 → 等待下次探测窗口。**

核心思路：不为每个 task 类型写特殊判断代码，而是**利用 brain 本身的行为引擎**来回答"有活没活"。

---

## 探测状态机

```
┌─────────────────────────────────────────────────────┐
│                   每 CHECK_INTERVAL tick             │
│                                                      │
│  ┌─── 攻击优先检查（见下方）←──────────────────┐    │
│  │                                                │    │
│  ▼                                                │    │
│  当前任务是否持续 idle ≥ ProbeGraceTicks？         │    │
│  │                                                │    │
│  ├── 否 → 记录/更新 lastNonIdleTick → 退出         │    │
│  │                                                │    │
│  └── 是 → 检查是否在探针冷却中                     │    │
│           │                                        │    │
│           ├── 在冷却中 → 退出                       │    │
│           │                                        │    │
│           └── 不在冷却 → 启动探测轮次               │    │
│                │                                   │    │
│                ▼                                   │    │
│           ┌─────────────────────┐                 │    │
│           │  probeIndex = 0     │                 │    │
│           │  excluded = [当前]  │                 │    │
│           └────────┬────────────┘                 │    │
│                    │                               │    │
│         ┌──────────▼──────────┐                   │    │
│         │ 切换到 task[i]      │                   │    │
│         │ probeTick = now     │                   │    │
│         └──────────┬──────────┘                   │    │
│                    │                               │    │
│             等待 ProbeWaitTicks                    │    │
│                    │                               │    │
│         ┌──────────▼──────────┐                   │    │
│         │ isMaidBrainIdle?    │                   │    │
│         │                     │                   │    │
│         │ idle → task[i]无活  │                   │    │
│         │   → 加入 excluded   │                   │    │
│         │   → probeIndex++    │                   │    │
│         │   → 下一个候选      │                   │    │
│         │                     │                   │    │
│         │ non-idle → 有活！   │                   │    │
│         │   → 停留此任务      │                   │    │
│         │   → 探针完成        │                   │    │
│         └──────────┬──────────┘                   │    │
│                    │                               │    │
│              全部排除？                            │    │
│               → 进入探针冷却                        │    │
│               → 留在最后一个探测的任务               │    │
│               → 等待 ProbeCooldown ticks            │    │
│               → 冷却结束 → 清除排除、重试            │    │
└─────────────────────────────────────────────────────┘
```

## 攻击优先抢占

**与探针并行运行**，不依赖空闲状态：

```
每 CHECK_INTERVAL tick：
  遍历优先级列表，找所有 IAttackTask：
    调用 findFirstValidAttackTarget(maid)
    若 isPresent() 且 该任务 ≠ 当前任务：
      → 无条件切换（打断探针、打断工作）
      → 设置 cooldowns，防止立刻被拉走
```

配置 `AttackPreempt` 控制是否启用（默认 true）。

## 配置新增

在 `PriorityConfig.java` 的 `multi_task` 段增加：

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `ProbeGraceTicks` | int (1~60) | 5 | 连续空闲多少 tick 后触发探测 |
| `ProbeWaitTicks` | int (1~10) | 3 | 探针切换到读取结果等待 tick 数 |
| `ProbeCooldown` | int (20~6000) | 200 | 全无活后重新探测的冷却 tick |
| `AttackPreempt` | boolean | true | 攻击任务是否无条件抢占 |

`COOLDOWN`（PollInterval）语义调整为"两次**有效切换**之间的最小间隔"，防止频繁抖动。

## 兼容性分析

### 对主模组原生任务

| 任务类型 | 工作方式 | 探针兼容性 |
|----------|---------|-----------|
| 近战/远程攻击 | `findFirstValidAttackTarget` 传感器 | ✅ 切过去传感器填充 ATTACK_TARGET |
| 农耕 | `MaidFarmMoveTask.searchForDestination` BFS | ✅ 切过去 BFS 设置 TARGET_POS |
| 除草/除雪/采蜜等 | 同上，该类继承 `MaidMoveToBlockTask` | ✅ 同上 |
| 灭火 | 搜索火焰方块 | ✅ 同上 |
| 钓鱼 | 搜索水源 | ✅ 同上 |
| 空闲 | `isEnable()` 始终 true，brain 始终 idle | ✅ 永远 idle，自然落到最低优先级 |

### 对其他附属 mod 添加的任务

探针方案对附属 mod **完全无侵入**。它不做任何任务类型判断：
1. `maid.setTask(candidateTask)` — 让 brain 运行该 task 的 `createBrainTasks()` 行为
2. 等待 `ProbeWaitTicks`
3. 读 brain 内存：`ATTACK_TARGET`/`WALK_TARGET`/`PATH`/`TARGET_POS`

**兼容条件**（附属 mod 任务必须满足，这是主模组的基础契约）：
- 任务通过 `registerAITool` / `IMaidTask` 注册到 `TaskManager`
- `createBrainTasks()` 返回有效的 Brain 行为列表
- 行为在激活时会设置 brain 内存（`WALK_TARGET` / `TARGET_POS` 等）

**不兼容情况**（几乎不会出现）：
- 任务使用非 brain 的旧 AI 系统（Entity Goals）
- 任务的 `isEnable()` 在探针切换时返回 false（会被 `findBestTask` 过滤，不会进入探针）

### 对比原方案的优势

| 维度 | 外部 API 预判方案 | 探针方案 |
|------|-----------------|---------|
| 攻击任务 | 需 `findFirstValidAttackTarget` | ✅ 统一走探针 |
| 农耕/除草 | 无法判断 | ✅ 切过去 BFS 搜索 |
| 附属 mod 任务 | 类型未知，完全无法处理 | ✅ 只要是 brain-based 任务就能工作 |
| 代码复杂度 | 每个任务类型需特殊判断 | 零任务类型判断 |

## 验证方式

1. 农耕有活 + 无怪：女仆稳定在农耕，不触发探针
2. 农耕闲置 ≥5 tick + 除草有活：探针切到除草，检测到有活 → 停留除草
3. 全部无活：探针遍历全部，进入冷却 200 tick，期间攻击有怪 → 抢占打断冷却 → 切攻击
4. 农耕有活 + 突然有怪：攻击抢占路径 → 无条件切攻击 ✓
