# 1.21.1 NeoForge 兼容迁移计划

> 状态：规划中（未开始实施）  
> 创建日期：2026-08-12  
> 源版本：Forge 1.20.1 + TLM `1.5.3-forge+mc1.20.1`  
> 目标版本：NeoForge 1.21.1 + TLM `1.5.3-neoforge+mc1.21.1`  
> 分支建议：`1.21.1`（长期维护线，与主模组分支命名对齐）

---

## 0. 结论摘要

| 项 | 决策 |
|---|---|
| 加载器 | **必须** Forge → **NeoForge**（TLM 1.21.1 仅发 NeoForge 包） |
| Java | 17 → **21** |
| 主模组 | 对齐 `1.5.3-neoforge+mc1.21.1`（与当前 1.20.1 的 1.5.3 功能线同代） |
| 仓库策略 | **双分支并行**：`main` 继续 1.20.1-Forge；`1.21.1` 专线 NeoForge |
| 架构策略 | **单加载器分支**（不做 Architectury 多加载器），降低一次性成本 |
| 附属 API | `ILittleMaid` / `@LittleMaidExtension` **仍存在**，AI Tool / Context / TaskData 入口可沿用 |
| 最大风险面 | 网络包、事件总线、配置 GUI、Mixin 目标、Menu/Screen、ResourceLocation |

**本计划只做规划，不自动切分支、不自动改代码、不自动 `runClient`/`commit`。**

## 1. 现状盘点

### 1.1 工程基线

- `gradle.properties`：`minecraft_version=1.20.1`，`forge_version=47.4.0`，Java 17
- 构建：ForgeGradle 6 + MixinGradle + Parchment
- 元数据：`META-INF/mods.toml` + `pack.mcmeta` pack_format **15**
- 入口：`SincerelyExtension` 同时 `@Mod` + `@LittleMaidExtension` + `implements ILittleMaid`
- 源码规模：约 **83** 个 Java 文件；**6** 个 Mixin

### 1.2 功能模块（迁移时按模块验收）

| 模块 | 关键路径 | 迁移敏感度 |
|---|---|---|
| 入口 / 生命周期 | `SincerelyExtension` | 高 |
| 聊天栏对话 | `chatbar/*`, `ChatCommand` | 中（事件改名） |
| 简易记忆 | `memory/*`, `MaidMemoryTool`, `MemoryGuidanceMixin` | 中 |
| 自动工作 v2 | `priority/**`, `autowork/**`, 11 个 packet | **很高** |
| GUI | `client/gui/**`, Menu/Container | 高 |
| 配置 | `ForgeConfigSpec` + Cloth Config | 中 |
| Mixin | `mixin/*` | 高（需对照 TLM 1.21 jar） |
| 兼容检测器 | `priority/detection/compat/*` | 中（依赖可选附属） |
| harness | `tools/memory-harness` | 低（纯 TS/Java 权威，无 Forge） |

### 1.3 当前工作区注意

`main` 上存在**未提交**改动（自动工作稳定性 / 附属兼容相关）。开分支前必须先处理：

1. **推荐**：先在 `main` 收尾并提交 1.20.1 稳定性改动，再从干净提交切 `1.21.1`  
2. 或：把 WIP stash / 临时提交后切分支，再决定是否带回 1.21.1  
3. **禁止**：在脏工作树上直接大范围改构建系统，导致 1.20.1 与 1.21.1 改动混杂

## 2. 目标环境锁定

### 2.1 官方基线（已核实）

| 组件 | 坐标 / 版本 |
|---|---|
| Minecraft | `1.21.1`，range 建议 `[1.21.1,1.21.2)` |
| NeoForge | 主模组当前为 `21.1.219`，range `[21,)` |
| Mappings | Parchment `1.21.1` + `2024.11.17`（与 TLM 1.21 一致） |
| TLM | `maven.modrinth:touhou-little-maid:1.5.3-neoforge+mc1.21.1` |
| Java | **21** |
| 元数据 | `META-INF/neoforge.mods.toml`（不再用 `mods.toml`） |
| pack_format | 1.21.x 需升到 **34**（或与 MDK 模板一致） |

### 2.2 必需依赖

| 依赖 | 1.20.1 现状 | 1.21.1 目标 |
|---|---|---|
| TLM | `1.5.3-forge+mc1.20.1` | `1.5.3-neoforge+mc1.21.1` |
| Cloth Config | `libs:cloth-config-forge:11.1.136` | NeoForge 对应线（约 v15 / 1.21.1 发布物，实施时以 Modrinth 精确坐标锁定） |

### 2.3 开发 runtimeOnly（可分期）

1.20.1 的 `runtimeOnly` 清单很长（JEI、Jade、Curios、FD、Create、女仆厨房等）。1.21.1 首轮：

- **P0**：仅 TLM + Cloth Config（保证最小可启动）
- **P1**：按「自动工作兼容检测器」实际需要逐个补 1.21.1 NeoForge 版
- **P2**：其余 QoL（Catalogue/Configured 等）有则加，无则跳过

## 3. 分支与版本策略

### 3.1 Git

```text
main (1.20.1 Forge) ──继续维护──►
         │
         └── branch 1.21.1 ──NeoForge 迁移──► 长期并行
```

建议操作顺序：

1. `main` 处理完 WIP 并确认可构建  
2. `git checkout -b 1.21.1`  
3. 在该分支完成构建系统与代码迁移  
4. 版本号策略（二选一，实施前确认）：  
   - **A（推荐）**：`mod_version` 继续 `0.1.0`，产物名带 MC/loader：`tlm_sincerely-1.21.1-neoforge-0.1.0`  
   - **B**：升 minor / 用 `0.1.0+1.21.1` semver 元数据

### 3.2 不采用的方案（本阶段）

- **Architectury 多加载器 monorepo**：成本过高，当前无 Fabric 需求  
- **同一分支条件编译双加载器**：维护成本高，易回归  
- **继续挂 Forge 1.21**：与 TLM 官方分发不一致

## 4. 技术迁移地图（按风险）

### 4.1 构建与工程（P0，阻塞一切）

| 变更 | 说明 |
|---|---|
| 插件 | `net.minecraftforge.gradle` → `net.neoforged.moddev`（ModDevGradle） |
| Mixin | MixinGradle 旧插件通常可去掉；NeoForge 用 `[[mixins]]` + jar 内 mixin 配置 |
| `archivesBaseName` | 改为 `…-1.21.1-neoforge` |
| toolchain | Java 21 |
| `mods.toml` | 重命名/替换为 `neoforge.mods.toml`，`forge` 依赖改为 `neoforge`，`mandatory` 改为 `type="required"` |
| `processResources` | 扩展属性改为 neo 变量名 |
| reobf | NeoForge/MDG 流程与 FG6 不同，删除 `reobfJar` 相关假设 |
| `DEVELOPMENT.md` / `AGENTS.md` | 分支内更新 Java 21 路径、构建命令、TLM jar 缓存路径 |

验收：空依赖可 `compileJava` 前，先能解析 NeoForge + TLM 依赖；最终 `./gradlew build` 成功。

### 4.2 入口与事件总线（P0）

| 1.20.1 Forge | 1.21.1 NeoForge |
|---|---|
| `FMLJavaModLoadingContext.get()` | 构造器注入 `IEventBus modEventBus` |
| `MinecraftForge.EVENT_BUS` | `NeoForge.EVENT_BUS` |
| `ModLoadingContext.get().registerConfig` | `modContainer.registerConfig` / Neo 等价 API |
| `TickEvent.ServerTickEvent` + `phase` | `ServerTickEvent.Post`（或 Neo 分相事件） |
| `ServerChatEvent` | 确认 Neo 包名与字段（`net.neoforged.neoforge.event.*`） |
| `PlayerEvent.PlayerLoggedInEvent` | 同系迁移 |
| `ClientPlayerNetworkEvent.LoggingOut` | 同系迁移 |
| `@OnlyIn(Dist.CLIENT)` | `net.neoforged.api.distmarker.*` |

`@Mod` + `@LittleMaidExtension` 双重实例化问题在 1.21 **仍可能存在**，保留 `configRegistered` / `argumentTypesRegistered` 防重入。

### 4.3 注册与 Menu（P0）

| 项 | 迁移要点 |
|---|---|
| `DeferredRegister` / `RegistryObject` | 改为 NeoForge `DeferredRegister` + `DeferredHolder`（或 MDG 推荐写法） |
| `AutoWorkMenus` | MenuType 注册挂到 mod bus；`IMenuTypeExtension.create` 等 Neo 工厂 |
| `ArgumentTypeInfos.registerByClass` | 确认 1.21 仍可用；时机仍要早于登录同步命令树 |

### 4.4 网络（P0，最高代码改写量之一）

现状：`SimpleChannel` + 手动 index + `FriendlyByteBuf` encode/decode + `NetworkEvent.Context`。

NeoForge 1.21 标准：

- `Payload` / `CustomPacketPayload` + `StreamCodec`
- `PayloadRegistrar`（`RegisterPayloadHandlersEvent`）
- 方向与处理线程由 registrar 约束

工作量：

- 重写 `AutoWorkNetworking`
- 11 个 packet 类全部改为 Payload 形态（C2S ×10 + S2C ×1）
- 客户端处理从 `NetworkEvent` 改为 payload handler
- 协议版本策略改用 payload id / 协议协商，而不是旧 `PROTOCOL_VERSION` 字符串（可保留业务兼容注释）

### 4.5 ResourceLocation 与数据包路径（P1）

- `new ResourceLocation(ns, path)` / `new ResourceLocation(string)` → `ResourceLocation.fromNamespaceAndPath` / `ResourceLocation.parse`（或 `ResourceLocation.tryParse`）
- 全仓字符串构造点：预设 IO、兼容命令、GUI 贴图、TaskData key 等
- 若后续有 datagen/loot/tag：注意 1.21 单数路径（`loot_table`、`tags/block`）；本模组目前资源以 assets/lang/mixin 为主，风险可控

### 4.6 GUI / 渲染（P1）

| 点 | 风险 |
|---|---|
| `AbstractContainerScreen` / 按钮 API | 方法签名、blit、tooltip 在 1.21 有差异 |
| `AutoWorkConfigScreen` 等手绘 UI | 需对照 1.21 Screen API 逐项编译修复 |
| 侧栏 Mixin（`MaidTabs` / `AbstractMaidContainerGui`） | **强依赖 TLM 1.21 类结构** |
| Cloth Config 扩展点 | `ModLoadingContext.registerExtensionPoint` → Neo `RegisterClientExtensions` / ConfigScreen 工厂等价物 |

### 4.7 配置（P1）

- `ForgeConfigSpec` → NeoForge 仍提供兼容风格 `ModConfigSpec`（包名变更，API 近似）
- 配置文件路径/文件名可能变化，文档中说明玩家需重新确认配置
- 不保证跨版本自动迁移旧 `config/tlm_sincerely-common.toml`（可后续做迁移器，非首期）

### 4.8 Mixin（P1，功能正确性关键）

| Mixin | 目标 | 策略 |
|---|---|---|
| `MemoryGuidanceMixin` | `MaidAIChatManager.buildMessage` | 反编译 1.21 TLM jar，核对方法签名与 redirect 目标 |
| `MaidChatBroadcastMixin` / `ChatBubbleSilenceMixin` | `ChatBubbleManager` | 核对 `addLLMChatText` / `addThinkingText` |
| `TtsSilenceMixin` | `MaidAIChatManager.tts` | 核对是否仍存在 |
| `MaidTabsMixin` | `MaidTabs.getTabs` | GUI 结构变化则重写 |
| `AbstractMaidContainerGuiMixin` | tooltip / taskButtonPressed | 同上 |

`mixins.json`：`compatibilityLevel` 升到 `JAVA_21`；Neo 下 refmap 策略按 MDG 文档调整。

### 4.9 TLM 附属 API（相对友好）

已从 TLM `1.21` 分支核实：

- `@LittleMaidExtension` 仍在
- `ILittleMaid` 仍含：
  - `registerAITool`
  - `registerAIMaidContext`
  - `registerTaskData`
- 包名主体 `com.github.tartaricacid.touhoulittlemaid.*` 保持

仍需在 **release jar** 上二次核实（GitHub `1.21` 可能略领先/滞后正式 1.5.3）：

- `TaskDataRegister` / `AutoWorkState` 编解码
- `EntityMaid` 任务切换、`IAttackTask` / `IFarmTask`
- `GameContextRegister.registerCategory` 重载（1.21 接口示例中 category 注册参数可能与现码细微差异）
- AI Tool schema 构建 API

### 4.10 业务逻辑（多数可保留）

以下以纯逻辑为主，预期 **少改**：

- 记忆 CRUD / 淘汰 / tidy
- 自动工作决策引擎、检测调度、预设 JSON
- MaidFinder 模糊匹配
- harness / golden（与 MC 版本解耦）

但只要触及 `EntityMaid`、Level、Server、Registry 类型，仍会有编译级修复。

## 6. 风险登记

| ID | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | TLM GUI 类重构导致侧栏 Mixin 失效 | 自动工作入口消失 | 阶段 2 优先反编译核对；必要时改为 TLM 官方扩展点（若有） |
| R2 | AI `buildMessage` / ChatBubble API 变更 | 记忆引导、广播、静音失效 | jar 级方法签名对比后再写 Mixin |
| R3 | 网络模型重写引入不同步 | GUI 空白/操作无效 | Payload 单测式 encode roundtrip + 游戏内快照对比 |
| R4 | Cloth Config Neo 扩展点变更 | 模组菜单进不去配置 | 查官方 1.21 示例；可临时用命令开配置 |
| R5 | 双重实例化在 Neo 生命周期下行为变化 | 配置/命令重复注册 | 保留静态防重入；观察构造调用次数 |
| R6 | 可选附属无 1.21 版 | 兼容检测器空转 | 检测器保持 soft depend；文档标明支持矩阵 |
| R7 | 主线 WIP 与迁移分支交叉污染 | 回滚困难 | 先清 main 再分支；禁止在 1.21.1 修 1.20.1-only 问题除非 cherry-pick |
| R8 | 玩家配置/预设 JSON 跨版本 | 行为差异 | 预设 JSON 尽量保持 schema；配置不保证自动迁移 |
