# 自动工作模式（工作自切换）

## 功能概述

自动工作模式（面向用户："自动切换工作 / Auto Switch Work"）让女仆根据周围情况自动切换工作模式。每只女仆独立维护是否启用自动调度及所选预设，预设库由服务端全局共享。排序方式统一为纯列表顺序，索引 0 为最高优先级。

## 架构（v2 重构后）

```text
AutoWorkPresetService (服务端共享预设库，UUID/name/order)
    ↕ per-maid presetId
AutoWorkStateService (每女仆 enabled + presetId，TLM TaskData 持久化)
    ↓
TaskDetectionScheduler -> MaidDetectionCache（按预设/检测世代）
    ↓
TaskSwitchDecisionEngine -> maid.setTask(realTask)
```

**核心设计**：自动工作模式不是 `IMaidTask`。`maid.getTask()` 始终为真实执行的工作（攻击、农耕等），自动调度状态独立存储，不随真实任务切换而丢失。

## 检测器与缓存

`TaskWorkDetectorRegistry` 支持第三方附属注册专用检测器：

```java
TaskWorkDetectorRegistry.register(taskUid, detector);
TaskWorkDetectorRegistry.registerFallback(MyTaskInterface.class, detector);
```

UID 精确注册优先于接口或类型 fallback。重复 `register` 会记录 WARN 并拒绝覆盖；明确需要替换时使用 `replace` 或 `replaceFallback`。

检测结果为不可变的 `DetectionResult`：

```java
public record DetectionResult(
        ResourceLocation taskUid,
        Availability availability,
        long sampledTick,
        int ttlTicks,
        int consecutiveConfirmations,
        String evidence,
        BlockPos targetPos,
        UUID targetEntityUuid
) {}
```

结果过期、检测异常、任务未注册、预算耗尽或没有检测器都会产生 `UNKNOWN`。未知不等于可用：系统不会以 `IMaidTask.isEnable()` 作为通用兜底，避免将女仆切入没有真实目标的附属工作。

### 附属兼容边界

内置 fallback 仅覆盖 `IAttackTask` 与 `IFarmTask`。其他附属 `IMaidTask` 可以加入预设，但必须通过 `TaskWorkDetectorRegistry.register(...)` 或 `registerFallback(...)` 提供专用 Detector 后才会自动切入。当前运行日志已确认下列任务需要专用兼容：

- `touhou_little_maid:shears`、`touhou_little_maid:board_games`；
- `maid_useful_task:maid_tree`；
- `maidsoulkitchen:berries_farm`；
- `maid_storage_manager:storage_manage`。

无 Detector 的已配置任务会输出限流 WARN，保持为未知当前任务时会触发 `EXTERNAL_UNKNOWN_CURRENT` 保护，不会被自动系统错误抢走。后续稳定性与专用兼容工作见 [`plans/自动工作稳定性与附属兼容计划.md`](plans/自动工作稳定性与附属兼容计划.md)。

### 攻击检测

`AttackTaskWorkDetector` 对 `IAttackTask` 调用 `IAttackTask.findFirstValidAttackTarget(maid)`。普通模式下检测间隔为 10 tick；实验性攻击抢占打开时为 5 tick。决策引擎只消费检测缓存，不会重复查询攻击目标。

### 农耕检测

`FarmTaskWorkDetector` 对 `IFarmTask` 执行增量环形扫描：

- 中心为 Home 限制中心或女仆当前位置。
- 扫描范围为女仆工作范围，垂直范围为 2。
- 候选必须满足 Home 限制，非 Home 时必须靠近 Owner。
- 使用种子副本调用 `canHarvest()` / `canPlant()`；没有种子时依然检查收获。
- 每个农耕检测器单次最多处理 64 个方块；全局受 `DetectionBlockBudgetPerTick` 与 `PathCheckBudgetPerTick` 限制。
- 扫描未完成时保存 `TaskScanCursor` 并返回 `UNKNOWN`，下个 tick 从当前位置继续。

可达性检查只在发现可收获或可种植候选后调用 `maid.canPathReach()`。首次游戏内验证需确认该 API 不会干扰当前导航。

## 决策规则

1. 只考虑当前预设中存在、能通过 `isEnable(maid)` 的任务。
2. 按预设 `order` 列表顺序排序，索引越小优先级越高。
3. 候选连续达到 `AvailableConfirmations` 次 `AVAILABLE` 后才能切入。
4. 当前任务连续达到 `UnavailableConfirmations` 次 `UNAVAILABLE` 后才能离开。
5. 当前任务为 `AVAILABLE` 时稳定保持；`MinimumTaskHoldTicks` 结束后可升级到更高优先级的 `AVAILABLE` 任务。
6. 全部结果为 `UNKNOWN` 或 `UNAVAILABLE` 时不切换。
7. 当前任务不在预设、且其检测结果为 `UNKNOWN` 时（闲置任务除外），视作外部/附属手动接管并保持，避免自动系统覆盖未知真实任务。

启用自动工作、切换预设、创建并绑定预设时会请求一次立即评估，绕过轮询等待但仍遵守可用性检测与最短持有时间。当前立即评估会消费缓存；后续计划将其升级为“先重扫新预设，再评估”。

玩家手动选择普通工作模式时，GUI 会先发送 `SetMaidAutoWork(false)` 关闭自动调度，再由主模组执行任务切换。其他附属或命令修改真实任务时，自动状态保持不变，系统会给予短宽限期避免抢夺。

## 生命周期

`TaskDetectionRuntimeState` 以服务器实例隔离检测缓存、扫描游标和决策状态：

- `ServerStarting` 创建新会话状态，`AutoWorkPresetService` 和 `AutoWorkStateService` 绑定服务器实例。
- `ServerStopped` 清空全部状态并解绑。
- 女仆死亡或离开 Level 时清理对应 UUID。
- 启用/切换预设产生的一次性立即评估请求也会在女仆离开、死亡、服务器启动/停止时清理。
- 若检测到 tick 回退，运行时状态重置。

这避免了集成服务器退出世界后将旧冷却或扫描时间戳带入新世界。

## 预设与界面（v2）

### 数据模型

- `AutoWorkPreset`：UUID、名称、纯 `List<ResourceLocation> order`（位置即优先级）。
- `AutoWorkState`：每女仆持久化 `enabled` + `presetId(UUID)`，通过 TLM `TaskDataRegister` 存储。
- `AutoWorkPresetService`：服务端全局共享预设库，按 `MinecraftServer` 生命周期管理。
- 预设文件 `auto_work_presets.json` 使用 v3 格式（`version: 3`），含 `defaultPreset` 和 `presets[id, name, order]`；旧 v1/v2 自动迁移并备份。

### 网络协议

客户端 GUI 不直接读写 JSON。所有操作通过 C2S 包发到服务端校验后原子保存：

| C2S 包 | 作用 |
|--------|------|
| `RequestAutoWorkSnapshotC2SPacket` | 请求快照 |
| `SetMaidAutoWorkC2SPacket` | 启用/关闭自动调度 |
| `SetMaidAutoWorkPresetC2SPacket` | 为女仆选择预设 |
| `CreatePresetC2SPacket` | 新建预设；GUI 提供当前女仆 UUID 时，服务端校验权限后原子绑定新预设 |
| `Rename/DeletePresetC2SPacket` | 预设改名/删除 |
| `Add/Remove/MovePresetTaskC2SPacket` | 预设内任务操作 |
| `OpenAutoWorkConfigC2SPacket` | 打开独立配置 GUI |

S2C 通过 `AutoWorkSnapshotS2CPacket` 推送完整快照。新建预设后的快照以服务端女仆状态为准，GUI 会自动跳转到新预设；Agent 修改预设库后会广播快照给在线客户端。

### GUI

- **底部开关**：女仆立绘下方 `AutoWorkVirtualTaskButton`（69×29），四态纹理取自 `maid_gui_sincerely.png`（v0 正常未开启 / v30 全局关闭未开启 / v60 正常开启 / v90 全局关闭开启），实际点击区域限于纹理内 (4,8) 起的 63×19，文字按点击区数学居中。无时钟图标、无蓝框、无状态色，统一黑色文字。
- **配置入口**：顶部水平 Tab 第 4 槽（`MaidTabs` Mixin `getTabs` RETURN），Tab 图标取自 `maid_gui_sincerely.png` (u=171, v=0, 16×16)，背景切片取自 `maid_gui_side.png`。
- **配置页面**：`AutoWorkConfigScreen extends AbstractMaidContainerGui`，面板背景从 `maid_gui_main.png` (80,28,176×137) 1:1 blit。双栏任务列表 5 行 × 73×16，条目纹理取自 `maid_gui_sincerely.png` (u=97, v=0)，选中态 (u=97, v=17)（悬停与点击选中均触发）。按钮纹理参数化：预设栏/任务行用 gui 纹理，控制按钮用 task 纹理，hover 偏移 v+14。预设名称 EditBox 实时保存（`setResponder`，无需确认按钮）。配置文件份数以 `当前/总数` 格式显示。
- **选中状态追踪**：右列任务选中状态以任务 UID（`ResourceLocation`）追踪而非列表索引，避免移动/重排后丢失选中。
- **手动接管**：`AbstractMaidContainerGuiMixin` 在 `taskButtonPressed` HEAD 注入先发送 `SetMaidAutoWork(false)`，确保玩家手动选择普通任务时自动退出自动模式。

## 配置

```toml
[multi_task]
Enabled = true
PollInterval = 100
ExperimentalAttackPreempt = false
ForceBrainRefreshOnStuck = true
AvailableConfirmations = 1
UnavailableConfirmations = 2
MinimumTaskHoldTicks = 60
DetectionBlockBudgetPerTick = 256
PathCheckBudgetPerTick = 4
```

`Enabled` 是自动工作模式的全局开关，**默认开启**。关闭后 `TaskAutoSwitchHandler` 会在 server tick 入口直接 `return`，女仆不再参与自动调度；但是：

- 女仆当前真实任务（`maid.getTask()`）不会被清空或重置；
- 每女仆的 `AutoWorkState`（enabled + presetId）不会被修改；
- 重新打开后调度从既有状态继续，无需重新建索引或清空预设。

配置键名沿用 `multi_task` 以保持向后兼容；面向用户的显示名统一为"自动工作模式 / Auto Work Mode"，界面入口为"自动切换工作 / Auto Switch Work"。GUI 中全局开关关闭时，底部按钮纹理自动切换到对应四态（未开启+全局关闭 / 已开启+全局关闭），文字统一黑色。

`ExperimentalAttackPreempt` 只控制立即攻击抢占，不控制攻击任务是否参与普通优先级排序。它仅在自动工作模式开启、预设包含攻击任务且存在有效攻击目标时才生效，并在目标消失后恢复抢占前的可用任务。

`ForceBrainRefreshOnStuck` 默认开启。自动切换后，如果当前任务的独立检测结果仍为 `AVAILABLE`，但连续 60 tick 没有产生 `ATTACK_TARGET`、`WALK_TARGET`、`PATH` 或 `TARGET_POS`，系统会额外调用一次主模组 `refreshBrain()`，重建 Behavior 并重置其首次检查状态。每次自动切换最多触发一次；若与其他修改女仆 AI 的附属冲突，可关闭该项。

旧版 `AttackPreempt`、`ProbeGraceTicks`、`ProbeWaitTicks`、`ProbeCooldown` 已从 ForgeConfigSpec 中移除。新系统只使用独立的 `ExperimentalAttackPreempt`，且默认关闭；旧 `AttackPreempt=true` 不会迁移或开启实验性抢占。

## AI Tool

`AutoWorkTool`（`auto_work`）支持服务端权威查询与操作：

| action | 作用 |
|--------|------|
| `query` | 查询预设库与女仆当前自动状态 |
| `set_auto_enabled` | 启用/关闭指定女仆的自动调度 |
| `select_preset` | 为女仆选择预设 |
| `create/rename/delete_preset` | 预设 CRUD |
| `add/remove/move_task` | 预设内任务排序 |

`query` 会列出所有预设及其完整任务顺序和显示名；`set_auto_enabled` 未指定 `preset_id` 时使用女仆当前有效预设或默认预设。Agent 修改自动状态/预设时也请求一次立即评估。

`MaidAutoWorkContext` 会以自然语言追加全局调度状态、女仆自动工作状态、有效预设和完整任务顺序；不使用额外布尔字段表达上下文。

不再使用数字优先级（1-10），统一为纯列表位置。

## 手动验证重点

1. 当前农耕任务在 Brain Memory 间隙保持稳定，不在任务间横跳。
2. farm 无可用工作且 grass 可用时，只进行一次自然降级。
3. 高优先级任务出现后，在最短保持时间结束时升级。
4. 实验性攻击抢占关闭时，攻击遵守普通保持时间。
5. 实验性攻击抢占开启时，只有预设中配置的攻击任务可立即抢占并在目标消失后恢复。
6. 退出并重新进入世界后，自动切换立即正常工作且无旧 tick 阻塞。
7. 顶部 Tab 打开独立配置页后，原攻击/农耕等任务配置 Tab 不受影响。
8. 底部开关四态纹理正确切换，点击仅在 63×19 区域生效，tooltip 仅悬停在该区域内显示。
9. 旧版 JSON 迁移：v1（数字优先级）→ v2（纯列表）→ v3（UUID 预设）自动完成并备份原文件。
10. 专用服务器：客户端 GUI 不写本地 JSON，所有操作通过 C2S/S2C 包。
11. 配置面板背景纹理 1:1 对齐，无白底闪烁。
12. 右列任务选中后点击"↑"/"↓"移动，选中高亮跟随同一任务不丢失。
13. EditBox 改名实时保存（每字符即发），输入中途收到 snapshot 不中断编辑。
14. 新建预设后份数显示立即更新。
15. 新建预设后当前女仆自动绑定新 UUID，名称栏、份数与两侧任务列表跳转到新预设。
16. 启用自动工作或切换预设后，日志出现 `immediate evaluation requested/completed`，且切换只基于明确可用任务。
17. 预设包含无 Detector 的附属任务时，出现一次限流 `NO_DETECTOR` 提示，但任务不会被误判为可自动执行。
18. 多女仆农耕时检查 `FULL_SCAN_ALL_UNREACHABLE`、`PATH_BUDGET_EXHAUSTED` 与反向切换日志；稳定性优化按交接计划单独验收。
