| 文件 | 修改内容 |

| `TaskAutoSwitchHandler.java` | 在各关键分支添加 `LOGGER` 日志输出 |

### 日志插入点

在 `onServerTick()` 的每个 `return`/`continue`/切换前添加 `LOGGER.warn()`：

```
1. "AutoSwitch: tick triggered" — 每次方法进入（仅间隔 tick 时打印确认进入）
2. "AutoSwitch: ENABLED is false, skip" — ENABLED 为 false 时
3. "AutoSwitch: not interval tick N, skip" — 非间隔 tick 时（DEBUG 级别）
4. "AutoSwitch: no active preset, skip" — preset 为 null 时
5. "AutoSwitch: sortedTasks is empty, skip" — 任务列表为空时
6. "AutoSwitch: found N maids in LEVEL" — 找到 WORK 状态女仆数（每间隔 tick）
7. "AutoSwitch: maid UUID cooldown not ready" — 冷却未结束
8. "AutoSwitch: findBestTask returned NULL for maid UUID" — 无可用任务
9. "AutoSwitch: bestTask == currentTask (TASK), skip" — 无需切换
10. "AutoSwitch: SWITCH maid UUID from OLD to NEW" — 确实触发切换时
11. "AutoSwitch: findBestTask checking ID (isEnable=VAL)" — 每个任务检查结果
```

### 验证方式

1. 运行时查看 `run/logs/latest.log` 中 `[AutoSwitch]` 日志
2. 根据日志输出确定自动切换卡在哪个条件
3. 针对性修复

### 额外调查

若日志显示 `sortedTasks is empty`：
→ 检查 JSON 文件是否正确加载 → 可能是 `loaded` 标志时序问题

若日志显示 `findBestTask returned NULL`：
→ 检查 `isEnable()` 在服务端是否返回 false 对所有任务 → 可能是服务端/客户端条件差异

若日志显示 `found 0 maids in LEVEL`：
→ 女仆不在 WORK 活动状态 → 检查日程/活动逻辑

若日志完全没有出现（无任何 `AutoSwitch` 日志）：
→ 事件处理器未注册 → 检查 `@Mod.EventBusSubscriber` 或加 `modid` 参数
