# 多工作模式

## 功能概述

多工作模式根据活动预设中的优先级，在服务端自动选择女仆的工作任务。任务的工作可用性由独立检测器判断，真实任务只会在最终决策确认后切换一次。

## 架构

```text
TaskPriorityPreset / TaskPriorityManager
                 |
                 v
TaskWorkDetectorRegistry
  |- AttackTaskWorkDetector (IAttackTask)
  |- FarmTaskWorkDetector   (IFarmTask)
  `- UNKNOWN fallback       (未适配任务)
                 |
                 v
TaskDetectionScheduler -> MaidDetectionCache
                 |
                 v
TaskSwitchDecisionEngine -> maid.setTask()
```

### 线程和副作用约束

- 所有检测都在服务端主线程执行；禁止后台访问世界、实体、背包和 Brain。
- 检测器只能读取状态，不调用 `maid.setTask()`、`refreshBrain()`、`eraseMemory()`、`harvest()` 或 `plant()`。
- `TaskSwitchDecisionEngine` 是唯一可执行自动 `maid.setTask()` 的组件。
- `UNKNOWN` 不是 `UNAVAILABLE`，它只会保守保持当前任务。

## 检测器与缓存

`TaskWorkDetectorRegistry` 支持第三方附属注册专用检测器：

```java
TaskWorkDetectorRegistry.register(taskUid, detector);
TaskWorkDetectorRegistry.registerFallback(MyTaskInterface.class, detector);
```

UID 精确注册优先于接口或类型 fallback。重复 `register` 会记录 WARN 并拒绝覆盖；明确需要替换时使用 `replace` 或 `replaceFallback`。

检测结果为不可变的 `DetectionResult`：

```java
public record DetectionResult(
        ResourceLocation taskUid,
        Availability availability,
        long sampledTick,
        int ttlTicks,
        int consecutiveConfirmations,
        String evidence,
        BlockPos targetPos,
        UUID targetEntityUuid
) {}
```

结果过期、检测异常、任务未注册、预算耗尽或没有检测器都会产生 `UNKNOWN`。

### 攻击检测

`AttackTaskWorkDetector` 对 `IAttackTask` 调用 `IAttackTask.findFirstValidAttackTarget(maid)`。普通模式下检测间隔为 10 tick；实验性攻击抢占打开时为 5 tick。决策引擎只消费检测缓存，不会重复查询攻击目标。

### 农耕检测

`FarmTaskWorkDetector` 对 `IFarmTask` 执行增量环形扫描：

- 中心为 Home 限制中心或女仆当前位置。
- 扫描范围为女仆工作范围，垂直范围为 2。
- 候选必须满足 Home 限制，非 Home 时必须靠近 Owner。
- 使用种子副本调用 `canHarvest()` / `canPlant()`；没有种子时依然检查收获。
- 每个农耕检测器单次最多处理 64 个方块；全局受 `DetectionBlockBudgetPerTick` 与 `PathCheckBudgetPerTick` 限制。
- 扫描未完成时保存 `TaskScanCursor` 并返回 `UNKNOWN`，下个 tick 从当前位置继续。

可达性检查只在发现可收获或可种植候选后调用 `maid.canPathReach()`。首次游戏内验证需确认该 API 不会干扰当前导航。

## 决策规则

1. 只考虑当前预设中存在、能通过 `isEnable(maid)` 的任务。
2. 数字更小的优先级在前；数字相同保持预设中的手动顺序。
3. 候选连续达到 `AvailableConfirmations` 次 `AVAILABLE` 后才能切入。
4. 当前任务连续达到 `UnavailableConfirmations` 次 `UNAVAILABLE` 后才能离开。
5. 当前任务为 `AVAILABLE` 时稳定保持；`MinimumTaskHoldTicks` 结束后可升级到更高优先级的 `AVAILABLE` 任务。
6. 全部结果为 `UNKNOWN` 或 `UNAVAILABLE` 时不切换。

## 生命周期

`TaskDetectionRuntimeState` 以服务器实例隔离检测缓存、扫描游标和决策状态：

- `ServerStarting` 创建新会话状态。
- `ServerStopped` 清空全部状态。
- 女仆死亡或离开 Level 时清理对应 UUID。
- 若检测到 tick 回退，运行时状态重置。

这避免了集成服务器退出世界后将旧冷却或扫描时间戳带入新世界。

## 配置

```toml
[multi_task]
Enabled = false
PollInterval = 100
ExperimentalAttackPreempt = false
ForceBrainRefreshOnStuck = true
AvailableConfirmations = 1
UnavailableConfirmations = 2
MinimumTaskHoldTicks = 60
DetectionBlockBudgetPerTick = 256
PathCheckBudgetPerTick = 4
```

`ExperimentalAttackPreempt` 只控制立即攻击抢占，不控制攻击任务是否参与普通优先级排序。它仅在多工作模式开启、预设包含攻击任务且存在有效攻击目标时才生效，并在目标消失后恢复抢占前的可用任务。

`ForceBrainRefreshOnStuck` 默认开启。自动切换后，如果当前任务的独立检测结果仍为 `AVAILABLE`，但连续 60 tick 没有产生 `ATTACK_TARGET`、`WALK_TARGET`、`PATH` 或 `TARGET_POS`，系统会额外调用一次主模组 `refreshBrain()`，重建 Behavior 并重置其首次检查状态。每次自动切换最多触发一次；若与其他修改女仆 AI 的附属冲突，可关闭该项。

旧版 `AttackPreempt`、`ProbeGraceTicks`、`ProbeWaitTicks`、`ProbeCooldown` 已从 ForgeConfigSpec 中移除。新系统只使用独立的 `ExperimentalAttackPreempt`，且默认关闭；旧 `AttackPreempt=true` 不会迁移或开启实验性抢占。

## 预设与界面

- `TaskPriorityPreset` 保存任务优先级与同优先级顺序。
- `TaskPriorityManager` 将预设保存至 `config/tlm_sincerely/task_priority_presets.json`。
- `TaskPriorityScreen` 提供预设编辑、任务排序与总开关。
- `TaskPriorityTool` 支持 AI 查询、设置任务优先级和切换预设。

预设 JSON 格式保持不变：

```json
{
  "active": "默认预设",
  "presets": [
    {
      "name": "默认预设",
      "priorities": [
        { "task": "touhou_little_maid:attack", "priority": 1 }
      ],
      "order": ["touhou_little_maid:attack"]
    }
  ]
}
```

## 手动验证重点

1. 当前农耕任务在 Brain Memory 间隙保持稳定，不在任务间横跳。
2. farm 无可用工作且 grass 可用时，只进行一次自然降级。
3. 高优先级任务出现后，在最短保持时间结束时升级。
4. 实验性攻击抢占关闭时，攻击遵守普通保持时间。
5. 实验性攻击抢占开启时，只有预设中配置的攻击任务可立即抢占并在目标消失后恢复。
6. 退出并重新进入世界后，自动切换立即正常工作且无旧 tick 阻塞。
