# 女仆命令执行模块 - 开发文档

## 功能概述

新增 AI Tool `run_command`：女仆以**主人（玩家）身份**执行一条 Minecraft 命令，把执行结果回传给模型与主人。

**核心能力**：

- 执行身份固定为主人：`owner.createCommandSourceStack()`，位置、维度、朝向、`@s`、相对坐标、权限等级全部按主人计算
- 权限继承主人真实等级，可用 `MaxPermissionLevel` 只下调不上调；主人离线时拒绝执行
- 双重名单判定：Brigadier 解析树节点名 + 原始文本 token 扫描，任一命中即生效
- 黑名单命令硬拒绝（回环命令 `tlmchat` 等，防止模型自调用形成回环）
- 确认名单命令在开启确认后需要主人点击 `[确认]/[取消]/[本次游戏内不再确认]`
- 单请求链最多 3 次命令尝试，命令长度上限 1024，回传模型输出截断 2000
- 实际执行的命令（成功/失败）回显到主人聊天栏
- 审计日志写入 `logs/tlm_sincerely/command_audit.log`，默认 16 MB 轮转

## 架构与数据流

```
玩家消息 ──► LLM ──► ToolCall(run_command, command="give @s diamond 1")
                        │
                        ▼
              MaidCommandTool.onCallAsync（服务端线程）
              ① 规范化 + 长度/字符校验（NormalizedCommand）
              ② 限流计数（CommandRateLimiter，按 LLMCallback 身份）
              ③ 主人解析（maid.getOwner() instanceof ServerPlayer）
              ④ 双重名单判定（CommandClassifier）
                 ├─ 黑名单 ──────────────► 硬拒绝，仅回 tool result
                 ├─ 确认名单 + 确认开启 ─► 挂起（CommandConfirmationService）
                 └─ 其余 ────────────────► 直接执行
                        │
                        ▼
        MaidCommandExecutor.execute
        ⑤ owner.createCommandSourceStack().withSource(CommandRecorder)
           [.withPermission(min(主人等级, 上限))]
           → Commands.performPrefixedCommand(stack, cmd)
                        │
        ⑥ 输出拼接（去多余空行）→ 截断 2000 字符
        ⑦ 审计日志（CommandAuditLog）+ 主人聊天栏回执
        ⑧ callback.addToolResult(...) → 模型继续对话
```

确认挂起路径：

```
awaitConfirmation ─► Pending(token, maid, owner, command, hitName, deadline, callback, toolCallId)
                     │  主人收到仅自己可见的确认消息（三个可点击按钮）
                     ├─ /tlmconfirm run <token>   → 校验 → 执行 → complete(future)
                     ├─ /tlmconfirm trust <token> → 记录 (owner, hitName) 会话信任 → 执行 → complete
                     ├─ /tlmconfirm cancel <token> → complete(future, 已取消)
                     ├─ tick 扫描超时（默认 60 秒）→ complete(future, 超时取消)
                     └─ 主人登出 / 女仆死亡或被移除 / 服务器停止 → complete(future, 已取消)
```

## 权限模型

1. 执行栈来自主人：`ServerPlayer#createCommandSourceStack()`，因此 `/give @s ...` 给的是主人、`~ ~ ~` 是主人坐标、`@s` 是主人。
2. 权限上限（`MaxPermissionLevel`，默认 4 = 不限）：
   ```java
   CommandSourceStack stack = owner.createCommandSourceStack().withSource(recorder);
   int cap = MaidCommandConfig.MAX_PERMISSION_LEVEL.get();
   if (cap < 4 && stack.hasPermission(cap + 1)) {
       stack = stack.withPermission(cap);   // 只下调，不提升
   }
   ```
3. 主人离线：拒绝执行（`REJECTED_OWNER_OFFLINE`），不会降级为女仆权限 0。
4. 非 OP 主人：命令以 0 级权限执行，权限不足会变成失败文本返回模型，无副作用。

## 名单判定（双重判定）

**判定一：解析树节点名**（`CommandClassifier.collectTreeNames`）

- 用服务器命令树 `dispatcher.parse(command, server.createCommandSourceStack().withSuppressedOutput())` 解析（仅取节点，不执行）
- 收集所有 `LiteralCommandNode` 名字，递归沿 `CommandContextBuilder#getChild()` 深入：
  - 原版 `/execute ... run <cmd>` 的 `run` 是 `literal("run").redirect(root)`，子命令节点只存在于 child context，不递归就会漏判
  - 实体选择器分支（`as`/`at`/`on`…）通过 `fork`/`redirect` 同样产生 child context
- 解析失败时本判定跳过，由判定二兜底

**判定二：原始文本扫描**（`CommandClassifier.scanTextNames`）

- 按空白切分，对每个 token 归一化后匹配；`run` 之后的首个 token 额外收一次
- 归一化：小写、去开头 `/`、去 `namespace:` 前缀（`minecraft:kill` → `kill`；配置项写带前缀或不带前缀均可匹配）

**优先级**：黑名单 > 确认名单 > 放行；两份名单的命中都在统一候选集上先查黑名单。

**默认黑名单**（回环命令）：`tlmchat, tlmmemory, tlmautowork, tlm, tlmconfirm`

**默认确认名单**（灭世级 + 管理级）：

```
kill, fill, setblock, clone, clear, datapack, function, reload, stop,
op, deop, ban, ban-ip, pardon, pardon-ip, kick, whitelist,
gamerule, difficulty, setworldspawn, worldborder, forceload, spreadplayers,
save-off, save-on
```

## 确认与会话信任

| 项 | 行为 |
|----|------|
| 触发条件 | 命中确认名单 **且** `ConfirmationEnabled=true`（默认关闭） |
| 消息 | 仅 `owner.sendSystemMessage`，含女仆名、命令原文、剩余有效时间与三个按钮 |
| 按钮 | `[确认]` → `/tlmconfirm run <token>`；`[取消]` → `cancel`；`[本次游戏内不再确认]` → `trust`（`SessionConfirmationEnabled=false` 时不渲染） |
| 超时 | `ConfirmationTimeoutSeconds`（默认 60，范围 10-600），tick 扫描（每 20 tick） |
| 并发 | 该女仆存在 pending 时，新对话被 HEAD 注入拒绝并提示先确认/取消 |
| 会话信任 | `Map<owner UUID, Set<hitName>>`，仅内存；`trust` 后同一登录会话内同根命令免确认，登出/停服清空 |
| 边界清理 | 主人登出、女仆死亡/移除、服务器停止都会取消 pending 并完成 future |

`hitName` 是分类判定命中的确认名单条目（例如 `/execute run fill ...` 命中 `fill`，信任粒度即 `fill`）。

## 配置清单（`[maid_command]`）

| 配置键 | 默认值 | 范围 | 说明 |
|--------|--------|------|------|
| `CommandToolEnabled` | true | bool | 工具总开关（关闭后不暴露给模型、不占 token） |
| `ConfirmationEnabled` | false | bool | 破坏性命令强制确认 |
| `SessionConfirmationEnabled` | true | bool | 允许"本次游戏内不再确认" |
| `ConfirmationTimeoutSeconds` | 60 | 10–600 | 确认超时 |
| `ConfirmationRequiredCommands` | 见上 | List | 强制确认名单 |
| `BlacklistedCommands` | 见上 | List | 硬拒绝名单 |
| `MaxPermissionLevel` | 4 | 0–4 | 主人权限上限（只下调） |
| `MaxCommandsPerRequest` | 3 | 1–16 | 单请求链命令尝试上限 |
| `MaxCommandLength` | 1024 | 16–4096 | 命令文本长度上限 |
| `ToolResultMaxChars` | 2000 | 200–20000 | 回传模型输出截断 |
| `AuditLogMaxSizeMb` | 16 | 1–1024 | 审计日志大小上限 |

## 审计日志

- 路径：`<gamedir>/logs/tlm_sincerely/command_audit.log`
- 格式（单行、不记输出全文）：

```text
2026-09-16T17:20:31Z maid="咲夜"(uuid) owner="terk"(uuid) decision=CONFIRMED_EXECUTED result=1 cmd="/give @s diamond 1" hit=-
```

- `decision`：`EXECUTED` / `CONFIRMED_EXECUTED` / `SESSION_TRUSTED_EXECUTED` / `CANCELLED` / `TIMEOUT` / `BLOCKED_BLACKLIST` / `REJECTED_OWNER_OFFLINE` / `RATE_LIMITED` / `INVALID` / `ERROR`
- 超过 `AuditLogMaxSizeMb` 后轮转为 `command_audit.log.1`（覆盖旧 `.1`）；写盘失败只 WARN，不影响命令流程

## 安全说明（给服主）

- **名单是缓解而非沙箱**：无法穷举所有模组命令与别名，请结合权限继承与审计日志使用
- 不要把本工具暴露给不可信玩家：女仆以主人身份执行命令，提示注入可能诱导破坏性操作
- 强烈建议多人服务器开启 `ConfirmationEnabled`，按需往确认名单里追加便利级命令（`tp / give / summon / effect / xp`）
- 回环命令（`tlmchat` 等）在黑名单中硬拒绝，模型无法用确认绕过
- 默认继承主人权限（不放大），因此工具不会让玩家获得其原本没有的权限
- 名单判定是保守策略：原文扫描会剥离任意 token 的 `namespace:` 前缀，资源 ID 恰为名单条目（如 `foo:tlm`）时会命中，属于"宁可多确认/多拒绝"
- 挂起时女仆气泡包含命令原文，会随实体数据同步给能看见该女仆的玩家；确认消息本身仅主人可见
- 审计记录的是规范化后的命令文本（无前导 `/`）

## 内置指令 Wiki Skill (`mc-command-1-20-1`)

为减少 LLM 在 1.20.1 环境下的指令幻觉（尤其是误用 1.20.5+ 的数据组件语法 `item[custom_name=...]` 或 1.12- 旧版废弃语法），模组内置随 jar 打包的数据包 Skill：

- **Skill 标识符**：`mc-command-1-20-1`
- **存放路径**：`data/touhou_little_maid/skills/mc-command-1-20-1/skill.md`（命名空间必须为 `touhou_little_maid`）
- **触发机制（惰性加载）**：
  - 其 description 明确约束模型**不在常规对话和简单命令中调用**，仅在先前 `run_command` 执行失败（语法错误、参数未知、NBT 解析异常等）或需构建高阶 1.20.1 复合指令（`/execute` 跨维链、多重 NBT、选择器安全过滤等）时调用。
  - 避免对话初期注入过多内容浪费 token，实现精准自愈。
- **核心指导范围**：
  - **版本断代禁区**：禁止 1.20.5+ 组件、禁止 1.20.1 不存在的指令（`/tick`、`/transfer` 等）、禁止修改玩家 NBT 原版限制。
  - **高阶模板**：`/execute` 链与跨维传送、选择器 `distance=..10` 与防误伤过滤、`/give` 复杂物品与药水 NBT、`/summon` 装备怪物、`/fill` 替换过滤、`/damage` 原生伤害。

## 排查

| 现象 | 可能原因 |
|------|----------|
| 模型从不调用工具 | `CommandToolEnabled=false`；或模型能力不足（summary 已说明身份与限制） |
| 返回"命令被永久拒绝" | 命中黑名单（默认含 `tlmchat/tlmmemory/tlmautowork/tlm/tlmconfirm`） |
| 返回"主人离线" | 主人不在线；本工具不会以女仆身份执行 |
| 命令执行失败（权限不足） | 主人真实权限等级不够；检查 `MaxPermissionLevel` 是否过低 |
| 点击确认按钮无效 | 确认已超时/已被处理；token 一次性，且校验点击者 UUID |
| 命令没执行但也没提示 | 挂起中：确认消息仅主人可见，请检查聊天栏与 `command_audit.log` |
| 审计日志没有新文件 | 检查 `logs/tlm_sincerely/` 是否可写；写盘失败只 WARN |
