# 简易记忆系统

## 需求概述

为女仆添加持久化的键值对记忆系统。记忆自动注入 AI 上下文、支持 AI Tool 自主读写、玩家可通过命令管理。

---

## 核心架构

### 三层接口 + 持久化层

```
┌─────────────────────────────────────────────────┐
│          玩家命令 (/tlmmemory)                     │  ← 命令层
│          set / get / list / forget / export       │
│          summarize                                │
├─────────────────────────────────────────────────┤
│          AI Tool (tlm_memory)                     │  ← AI Tool 层
│          remember / recall / forget               │
├─────────────────────────────────────────────────┤
│          AI Context (自动注入, promptContext=true) │  ← Context 层
│          core 记忆全文注入 + archive 记忆索引预览   │
├─────────────────────────────────────────────────┤
│          MaidMemoryManager (Gson JSON)            │  ← 持久化层
│          config/tlm_sincerely/maid_memories/       │
│            <uuid>.json                            │
├─────────────────────────────────────────────────┤
│          MemoryConfig (ForgeConfigSpec)           │  ← 配置层
│          maxMemories: 50, coreLimit: 10           │
└─────────────────────────────────────────────────┘
```

### 记忆搜索机制（索引预览 + 按需深读）

- **Context 自动注入**：全部记忆的 `key` + `前 30 字符截断` + `importance 标签`，AI 一眼看到有哪些记忆
- **AI 按需深读**：AI 从 context 预览中判断需要哪条的完整值，调用 `recall(key)` 获取全文
- **无需先 list 再 recall**：context 已包含索引，AI 可直达目标

### 记忆录入机制（Skill 引导 + 即时写入 + 按需总结）

- **Skill 引导**：`memory-guidance` Skill（数据包）在每次对话时自动可用，告知 AI 何时应使用 `remember`
- **AI 即时写入**：AI 在对话中判断重要信息，当场调用 `remember` Tool 写入，零额外 API 调用
- **玩家手动写入**：`/tlmmemory set` 命令
- **按需总结（兜底）**：`/tlmmemory summarize` 触发 AI 回顾本轮对话，补写遗漏

## 数据模型

### MaidMemory.java

```
字段: Map<String, MemoryEntry> memories (LinkedHashMap)
内嵌 record: MemoryEntry(String value, String importance, long createdAt, long updatedAt)
常量: CORE = "core", ARCHIVE = "archive"
方法: set/get/forget/keys/size/isEmpty/generateContextPreview
```

generateContextPreview 格式：
```
core 记忆（≤ 10 条）:  "fav_food: Pumpkin pie"
archive 记忆:         "last_gift: Received an iron sword..." (≤ 30 字符截断)
标签后缀:              "(core)" / "(archive)"
总计行:                "N memories total"
```

### JSON 文件格式

```json
{
  "memories": {
    "fav_food": {
      "value": "Pumpkin pie",
      "importance": "core",
      "createdAt": 1715472000000,
      "updatedAt": 1715472000000
    }
  }
}
```

## 详细设计

### 1. MaidMemory.java

```
package: com.github.tartaricacid.tlm_sincerely.memory

public class MaidMemory:
  - Map<String, MemoryEntry> memories (LinkedHashMap, 插入顺序)
  
  record MemoryEntry(String value, String importance, long createdAt, long updatedAt)
  
  void set(String key, String value, String importance):
    - key 长度限制 ≤ 64 字符，value ≤ 500 字符
    - importance 仅允许 "core" / "archive"
    - 若已存在 → 更新 value 和 updatedAt，保持 importance
    - 新增 → 设置 createdAt=updatedAt=System.currentTimeMillis()
  
  Optional<MemoryEntry> get(String key)
  void forget(String key)
  List<String> keys()
  int size()
  boolean isEmpty()
  
  String generateContextPreview(int coreLimit, int previewLength):
    - 分离 core 和 archive
    - core 按插入顺序取前 coreLimit 条，注入全文
    - archive 注入 key + "value" 前 previewLength 字符截断
    - 末尾追加 "N memories total, M core + A archive"
    - 返回格式化的多行字符串
```

### 2. MaidMemoryManager.java

```
package: com.github.tartaricacid.tlm_sincerely.memory

public final class MaidMemoryManager:
  static Gson GSON = new GsonBuilder().setPrettyPrinting().create()
  static Path MEMORY_DIR = FMLPaths.CONFIGDIR.get().resolve("tlm_sincerely/maid_memories")
  
  static MaidMemory load(UUID maidUuid):
    - 读取 config/tlm_sincerely/maid_memories/<uuid>.json
    - 反序列化 JSON → MaidMemory
    - 文件不存在 → 返回空 MaidMemory
  
  static void save(UUID maidUuid, MaidMemory memory):
    - 自动创建目录
    - 序列化 → 写入文件
    - IOException 静默忽略
  
  static int count(): 文件系统中 UUID 文件数量
```

### 3. MemoryConfig.java

```
package: com.github.tartaricacid.tlm_sincerely.config.subconfig

public final class MemoryConfig:
  static ForgeConfigSpec.BooleanValue ENABLED              // 默认 true
  static ForgeConfigSpec.IntValue MAX_MEMORIES             // 默认 50，范围 1-200
  static ForgeConfigSpec.IntValue CORE_LIMIT               // 默认 10，范围 0-50
  static ForgeConfigSpec.IntValue CONTEXT_PREVIEW_LENGTH    // 默认 30，范围 10-200
  
  static void init(ForgeConfigSpec.Builder builder):
    builder.push("memory")
    ENABLED = builder.define("Enabled", true)
    MAX_MEMORIES = builder.defineInRange("MaxMemories", 50, 1, 200)
    CORE_LIMIT = builder.defineInRange("CoreMemoryLimit", 10, 0, 50)
    CONTEXT_PREVIEW_LENGTH = builder.defineInRange("ContextPreviewLength", 30, 10, 200)
    builder.pop()
```

**注意**：`Enabled` 默认 `true`。记忆系统不会自动改变游戏行为（不像多工作模式自动切任务），只是为 AI 提供更多上下文，开启是更好的默认体验。Tool 和 Context 在 Enabled=false 时应返回禁用状态。

### 4. MaidMemoryContext.java

```
package: com.github.tartaricacid.tlm_sincerely.ai.context

public class MaidMemoryContext extends AbstractMaidContext:
  super("tlm_sincerely_memory_list", "Maid persistent memories")
  
  getValue(EntityMaid maid):
    - 获取 maid UUID
    - MaidMemoryManager.load(uuid)
    - 若 isEmpty → 返回 "None"
    - 调用 memory.generateContextPreview(
        MemoryConfig.CORE_LIMIT.get(),
        MemoryConfig.CONTEXT_PREVIEW_LENGTH.get())
    - 返回格式化后的文本
```

注册（在 SincerelyExtension.java）：
```java
register.registerCategory("tlm_sincerely_memory", "Maid persistent memories", true);
register.registerContext("tlm_sincerely_memory", new MaidMemoryContext());
```

### 5. MaidMemoryTool.java

```
package: com.github.tartaricacid.tlm_sincerely.ai.tool

public class MaidMemoryTool implements ITool<MaidMemoryTool.Result>:
  TOOL_ID = "tlm_memory"
  CODEC = RecordCodecBuilder: action, key, value, importance
  
  parameters(ObjectParameter root, EntityMaid maid):
    - action: StringParameter, enum=["remember", "recall", "forget"], required
    - key: StringParameter, 从当前女仆记忆中枚举已有 key 供补全, required=false
    - value: StringParameter, required=false
    - importance: StringParameter, enum=["core", "archive"], required=false
  
  onCall(toolCallId, result, callback):
    - 获取当前女仆 UUID: callback.getMaid().getUUID()
    - remember: 校验 key/value/importance → MaidMemoryManager.save()
    - recall: 查找 key → 返回完整值或 "not found"
    - forget: 删除 key → 返回确认
    - 注意: remember 时检查 MAX_MEMORIES 上限
  
  summary: "Manage persistent key-value memories for the maid. ..."

  record Result(String action, String key, String value, String importance)
```

### 6. Skill: memory-guidance

文件路径：`src/main/resources/data/touhou_little_maid/skills/memory-guidance/skill.md`

```markdown
---
name: memory-guidance
description: >
  Guides the maid on when and how to use the persistent memory system.
  Use this when the maid needs to remember player preferences,
  important facts, or relationship milestones.
---

# Memory System Guidelines

You have a persistent memory system. Use the `tlm_memory` tool to manage memories.

## When to call `remember`:
- Player explicitly asks you to remember something ("记住...", "remember this...")
- Player reveals personal preferences ("我喜欢...", "I like...", "我讨厌...", "I hate...")
- Player teaches you a fact you should retain for future conversations
- A significant event occurs (gift received, promise made, milestone achieved)

## When NOT to call `remember`:
- Casual greetings, weather comments, or small talk
- Temporary game state that changes frequently
- Things the player did not say to you directly
- Information that is already in `query_game_context`

## How to use `remember`:
- `key`: short semantic name (e.g. "player_hobby", not "stuff_1")
- `value`: concise sentence with full context (who, what, when, why)
- `importance`: use "core" for things the player explicitly asked you to remember or that define your relationship with them; use "archive" for contextual details

## How to use `forget`:
- Only forget things the player explicitly asks you to forget
- Do NOT forget memories on your own initiative

## Memory capacity:
- Limited number of memories. If near the limit, prioritize keeping "core" memories and forget old "archive" memories when the player asks you to remember something new.
```

### 7. MemoryCommand.java

```
package: com.github.tartaricacid.tlm_sincerely.command

命令树: /tlmmemory
├─ /tlmmemory set <maid_selector> <key> <value>
│   /tlmmemory set-core <maid_selector> <key> <value>
│   参数: maid_selector → "name" 或 "uuid:<UUID>"（Tab 补全女仆名）
│         key             → 自由文本
│         value           → 自由文本（含空格，贪婪匹配）
│   set = 归档记忆（archive），set-core = 核心记忆（core）
├─ /tlmmemory get <maid_selector> <key>
│   显示: key, value, importance, createdAt, updatedAt
├─ /tlmmemory list <maid_selector>
│   列出全部记忆: key, importance, value 前 30 字符
├─ /tlmmemory forget <maid_selector> <key>
│   删除指定记忆
├─ /tlmmemory export <maid_selector> [format]
│   format=json: 原始 JSON 文件内容
│   format=text: Markdown 可读格式
│   format=context: 模拟 AI 看到的完整 context
├─ /tlmmemory summarize <maid_selector>
│   找到女仆 → 发送系统消息到 AI 对话管道，触发回顾总结

maid_selector 支持两种格式:
  - "琪琪"           → MaidFinder.findByName 模糊匹配
  - "uuid:xxx-xxx"   → MaidFinder.findByUuid 精确匹配
```

**summarize 实现方案：**
```
获取 EntityMaid → maid.getAiChatManager().chat(
    new ChatClientInfo(player.getGameProfile(), 
        "请回顾你今天和我的所有对话，" +
        "把任何你遗漏的重要信息用 tlm_memory 的 remember 记录下来。" +
        "用 memory-guidance skill 来决定该记住什么。")
)
```

## 与主模组的兼容性

| 对接点 | 兼容性 |
|--------|--------|
| `registerAIContext` - 记忆分类 `tlm_sincerely_memory` | ✅ 独立分类，不与内置 status/world/equipment 等冲突 |
| `promptContext=true` - 自动注入 | ✅ 主模组将全部 promptContext=true 的分类拼入 <context> 块 |

| Tool 内 `callback.getMaid()` 获取女仆 | ✅ 已在 TaskPriorityTool 中验证可行 |
