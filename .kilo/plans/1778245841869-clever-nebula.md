# 工作任务优先级排序功能开发计划

## 需求概述

在主模组的任务切换界面中，实现一个任务优先级排序系统：

1. **双列布局**：左列显示未排序任务，右列显示已排序任务（含优先级数字）
2. **优先级数字**：通过 1-10 设置优先级，数字越小优先级越高
3. **点击标签启用**：点击任务标签启用排序，标签旁显示优先级数字
4. **同优先级排序**：同优先级内按任务标签顺序排序（可调节）
5. **AI 配置**：通过 ITool 让 AI 可以配置优先级
6. **配置文件**：已设定的排序可保存、切换、命名

## 技术方案

### 1. 数据存储

**优先级数据结构**：

```java
// 存储在配置文件中，支持多预设
public class TaskPriorityPreset {
    String name;                          // 预设名称
    Map<ResourceLocation, Integer> priorities;  // taskId -> priority (1-10)
    List<ResourceLocation> order;         // 同优先级内的顺序
}
```

**配置文件位置**：`config/tlm_sincerely/task_priority_presets.json`

### 2. GUI 实现

**方式**：使用 Mixin 在女仆界面上方的标签页栏（MaidTabs）中添加新标签，点击打开优先级配置界面

**入口**：在主模组的 `main`、`task_config`、`maid_config` 三个标签旁添加第四个标签 `priority`

**Mixin 目标**：

| 目标类 | 方法 | 注入点 | 功能 |
|--------|------|--------|------|
| `MaidTabs` | `getTabs()` | `@At("RETURN")` | 在返回的标签数组中追加优先级标签按钮 |
| `EntityMaid` | `openMaidGui(Player, int)` | `@At("HEAD")` | 拦截 TAB_INDEX_PRIORITY，返回优先级 GUI 的 MenuProvider |

**客户端流程**：
```
用户点击优先级标签 
  → MaidTabButton.onClick() 
  → ToggleTabMessage(entityId, TAB_INDEX_PRIORITY) 
  → 服务端 EntityMaid.openMaidGui(player, TAB_INDEX_PRIORITY) 
  → getGuiProvider(TAB_INDEX_PRIORITY) 
  → 返回自定义 MenuProvider 
  → 打开优先级配置 Container/Screen
```

**优先级配置界面布局**（ContainerGui 或独立 Screen）：
```
┌─────────────────────────────────────────────────────────────┐
│                    任务优先级配置                              │
├──────────────────────────────┬──────────────────────────────┤
│      未排序任务               │        已排序任务              │
│  ┌──────────────────────┐    │  ┌──────────────────────┐    │
│  │ [✓] 攻击模式          │    │  │ [1] 攻击模式          │    │
│  │ [✓] 弓箭攻击          │    │  │ [2] 弓箭攻击          │    │
│  │ [ ] 农业模式          │    │  │ [3] 钓鱼模式          │    │
│  │ [ ] 钓鱼模式          │    │  │                      │    │
│  │ ...                  │    │  │                      │    │
│  └──────────────────────┘    │  └──────────────────────┘    │
├──────────────────────────────┴──────────────────────────────┤
│  预设: [默认预设 ▼]  [保存] [加载] [新建] [删除]              │
│  [应用到女仆]  [取消]                                        │
└─────────────────────────────────────────────────────────────┘
```

**实现要点**：
- 自定义 `TAB_INDEX_PRIORITY = 5`（TabIndex 中未使用的值）
- Mixin `MaidTabs.getTabs()` 追加按钮，复用主模组的 `MaidTabButton` 组件
- Mixin `EntityMaid.getGuiProvider()` 在 switch 前拦截，返回自定义 MenuProvider
- 优先级 GUI 使用标准的 Container + ContainerGui 模式（与主模组一致）
- 需要自定义 `PriorityContainer`（服务端）和 `PriorityContainerGui`（客户端）

### 3. 自动切换逻辑

**实现方式**：条件触发式自动切换

**切换规则**：
- 每 20 tick（1秒）检查一次条件变化
- 遍历优先级列表（从高到低），找到第一个满足启用条件的任务
- 如果该任务优先级高于当前任务，自动切换
- 切换后设置冷却时间（防止频繁切换，默认 100 tick = 5秒）

**条件检查示例**：
```java
// 检查任务是否满足启用条件
public boolean isTaskAvailable(EntityMaid maid, IMaidTask task) {
    // 使用主模组已有的 isEnable() 方法
    return task.isEnable(maid);
}

// 选择最高优先级的可用任务
public IMaidTask selectHighestPriorityTask(EntityMaid maid) {
    for (Map.Entry<ResourceLocation, Integer> entry : sortedPriorities) {
        IMaidTask task = TaskManager.findTask(entry.getKey()).orElse(null);
        if (task != null && isTaskAvailable(maid, task)) {
            return task;
        }
    }
    return TaskManager.getIdleTask(); // 无可用任务时切换到待命
}
```

**实现要点**：
- 在服务端 Tick 事件中检查
- 只在女仆处于工作模式（WORK Activity）时触发
- 与主模组的 `IMaidTask.isEnable()` 方法集成

## 实现步骤

### Phase 1: 数据层
1. 创建 `TaskPriorityPreset` 数据类
   - 预设名称
   - 优先级映射（taskId → priority）
   - 同优先级内的顺序列表
2. 创建 `TaskPriorityManager` 管理器
   - 加载/保存 JSON 配置文件
   - 管理多个预设（CRUD 操作）
   - 提供 API 获取当前优先级
   - 持久化到 `config/tlm_sincerely/task_priority_presets.json`
3. 在 `SincerelyConfig` 中添加配置项
   - `TASK_PRIORITY_ENABLED`：是否启用优先级自动切换
   - `TASK_PRIORITY_COOLDOWN`：切换冷却时间（tick）

### Phase 2: Mixin 配置
1. `build.gradle` **已配置完成**（mixingradle 插件 + Mixin 块 + annotationProcessor + manifest MixinConfigs）
2. 创建 `src/main/resources/tlm_sincerely.mixins.json`
   ```json
   {
     "required": true,
     "minVersion": "0.8",
     "package": "com.github.tartaricacid.tlm_sincerely.mixin",
     "compatibilityLevel": "JAVA_8",
     "refmap": "tlm_sincerely.refmap.json",
     "mixins": [
       "EntityMaidGuiMixin"
     ],
     "client": [
       "MaidTabsMixin"
     ],
     "injectors": {
       "defaultRequire": 1
     }
   }
   ```
   ⚠️ **重要**：Mixin 0.8.5 最大支持 `JAVA_13`，使用 `JAVA_8` 确保兼容
3. 在 `mods.toml` 中添加 Mixin 配置引用
   ```toml
   [[mixins]]
   config = "tlm_sincerely.mixins.json"
   ```

### Phase 2.5: Mixin 实现注意事项
- **自定义方法需要 `remap = false`**：主模组/第三方 mod 的自定义方法没有 SRG 映射
  ```java
  @Inject(method = "getTabs", at = @At("RETURN"), remap = false)
  ```
- **Forge 补丁方法需要 `remap = false`**：如 `ServerPlayer.sendSystemMessage()` 是 Forge 添加的
- **MaidTabsMixin**：`@ModifyArg` 不适用，用 `@Inject` + 本地变量捕获返回值，再修改
- **EntityMaidGuiMixin**：`getGuiProvider` 返回 `MenuProvider`，在 `@HEAD` 注入位置不可直接修改返回值，需用 `@Inject` + `Cancellable` + `@Local` 捕获参数

## 风险与注意事项

1. **Mixin compatibilityLevel**：本项目使用 Mixin 0.8.5，`compatibilityLevel` 必须设为 `JAVA_8`（不能写 `JAVA_17`，否则 Mixin 类不会加载）
2. **Mixin remap = false**：注入主模组自定义方法时必须加 `remap = false`，否则编译失败
3. **MaidTabs.getTabs 返回数组**：Mixin `@At("RETURN")` 无法修改原始数组，需在回调中创建新数组替换返回值（通过 `@ModifyArg` 的 `index = 0` 或 `@Inject` 中修改返回值）
4. **GUI 贴图**：需要设计合适的贴图资源，或复用主模组现有贴图
5. **性能**：自动切换逻辑不宜过于频繁，建议每 20 tick 检查一次
6. **兼容性**：确保与主模组的任务切换机制不冲突
7. **数据持久化**：JSON 配置文件需要处理好并发读写
