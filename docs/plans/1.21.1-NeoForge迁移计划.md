## 0. 结论摘要

| 项 | 决策 |
|---|---|
| 加载器 | **必须** Forge → **NeoForge**（TLM 1.21.1 仅发 NeoForge 包） |
| Java | 17 → **21** |
| 主模组 | 对齐 `1.5.3-neoforge+mc1.21.1`（与当前 1.20.1 的 1.5.3 功能线同代） |
| 仓库策略 | **双分支并行**：`main` 继续 1.20.1-Forge；`1.21.1` 专线 NeoForge |
| 架构策略 | **单加载器分支**（不做 Architectury 多加载器），降低一次性成本 |
| 执行模式 | **单主代理总控 + 多子代理施工**，止步于人工验收门（`runClient` 需用户授权） |

| 最大风险面 | 网络包、事件总线、配置 GUI、Mixin 目标、Menu/Screen、ResourceLocation |

## 4. 技术迁移地图（按风险）

### 4.1 构建与工程（P0，阻塞一切）

| 变更 | 说明 |
|---|---|
| 插件 | `net.minecraftforge.gradle` → `net.neoforged.moddev`（ModDevGradle） |
| Mixin | MixinGradle 旧插件通常可去掉；NeoForge 用 `[[mixins]]` + jar 内 mixin 配置 |
| `archivesBaseName` | 改为 `…-1.21.1-neoforge` |
| toolchain | Java 21 |
| `mods.toml` | 重命名/替换为 `neoforge.mods.toml`，`forge` 依赖改为 `neoforge`，`mandatory` 改为 `type="required"` |
| `processResources` | 扩展属性改为 neo 变量名 |
| reobf | NeoForge/MDG 流程与 FG6 不同，删除 `reobfJar` 相关假设 |
| `DEVELOPMENT.md` / `AGENTS.md` | 分支内更新 Java 21 路径、构建命令、TLM jar 缓存路径 |

验收：空依赖可 `compileJava` 前，先能解析 NeoForge + TLM 依赖；最终 `./gradlew build` 成功。

### 4.2 入口与事件总线（P0）

| 1.20.1 Forge | 1.21.1 NeoForge |
|---|---|
| `FMLJavaModLoadingContext.get()` | 构造器注入 `IEventBus modEventBus` |
| `MinecraftForge.EVENT_BUS` | `NeoForge.EVENT_BUS` |
| `ModLoadingContext.get().registerConfig` | `modContainer.registerConfig` / Neo 等价 API |
| `TickEvent.ServerTickEvent` + `phase` | `ServerTickEvent.Post`（或 Neo 分相事件） |
| `ServerChatEvent` | 确认 Neo 包名与字段（`net.neoforged.neoforge.event.*`） |
| `PlayerEvent.PlayerLoggedInEvent` | 同系迁移 |
| `ClientPlayerNetworkEvent.LoggingOut` | 同系迁移 |
| `@OnlyIn(Dist.CLIENT)` | `net.neoforged.api.distmarker.*` |

`@Mod` + `@LittleMaidExtension` 双重实例化问题在 1.21 **仍可能存在**，保留 `configRegistered` / `argumentTypesRegistered` 防重入。

### 4.3 注册与 Menu（P0）

| 项 | 迁移要点 |
|---|---|
| `DeferredRegister` / `RegistryObject` | 改为 NeoForge `DeferredRegister` + `DeferredHolder`（或 MDG 推荐写法） |
| `AutoWorkMenus` | MenuType 注册挂到 mod bus；`IMenuTypeExtension.create` 等 Neo 工厂 |
| `ArgumentTypeInfos.registerByClass` | 确认 1.21 仍可用；时机仍要早于登录同步命令树 |

### 4.4 网络（P0，最高代码改写量之一）

现状：`SimpleChannel` + 手动 index + `FriendlyByteBuf` encode/decode + `NetworkEvent.Context`。

NeoForge 1.21 标准：

- `Payload` / `CustomPacketPayload` + `StreamCodec`
- `PayloadRegistrar`（`RegisterPayloadHandlersEvent`）
- 方向与处理线程由 registrar 约束

工作量：

- 重写 `AutoWorkNetworking`
- 11 个 packet 类全部改为 Payload 形态（C2S ×10 + S2C ×1）
- 客户端处理从 `NetworkEvent` 改为 payload handler
- 协议版本策略改用 payload id / 协议协商，而不是旧 `PROTOCOL_VERSION` 字符串（可保留业务兼容注释）

### 4.5 ResourceLocation 与数据包路径（P1）

- `new ResourceLocation(ns, path)` / `new ResourceLocation(string)` → `ResourceLocation.fromNamespaceAndPath` / `ResourceLocation.parse`（或 `ResourceLocation.tryParse`）
- 全仓字符串构造点：预设 IO、兼容命令、GUI 贴图、TaskData key 等
- 若后续有 datagen/loot/tag：注意 1.21 单数路径（`loot_table`、`tags/block`）；本模组目前资源以 assets/lang/mixin 为主，风险可控

### 4.6 GUI / 渲染（P1）

| 点 | 风险 |
|---|---|
| `AbstractContainerScreen` / 按钮 API | 方法签名、blit、tooltip 在 1.21 有差异 |
| `AutoWorkConfigScreen` 等手绘 UI | 需对照 1.21 Screen API 逐项编译修复 |
| 侧栏 Mixin（`MaidTabs` / `AbstractMaidContainerGui`） | **强依赖 TLM 1.21 类结构** |

## 5. 分阶段实施计划（主代理 + 子代理执行模型）

### 5.0 执行模式（已敲定）

- **单主代理**：总控进度、拆解与派发任务包、回收子代理结果、跑 `./gradlew build` 门禁、勾选计划项、阶段收口汇报；不做大段施工。
- **多个子代理**：一次只领一个任务包，交付「可编译代码 + 证据」（改动清单 / 编译输出 / jar 反编译摘录）。
- **人工验收门**：代理施工止步于阶段 2 出口（`./gradlew build` 成功）；阶段 3 `runClient` 与实机验收必须由用户明确授权（AGENTS 红线），`git commit` 同样由用户决定。

| 角色 | 职责 | 禁止 |
|---|---|---|
| 主代理 | 进度控制、任务包拆分派发、构建门禁、计划勾选、一致性收口 | 未过门禁进入下一阶段；替子代理大段施工 |
| 子代理 | 单一任务包编码 / jar 核对，交付证据 | 领包外改动；自行 `runClient`；自行 commit；跨文件改动不报告 |
| 用户 | 授权 `runClient`、实机验收、决定 commit | —— |

任务包原则：**包内自包含**（输入 = 相关文件 + 目标 API 约定；输出 = 代码 + 证据）；可并行的包不得同时写同一文件；有前置的包在任务卡上标明依赖（如 2.5 依赖 2.3+2.4 定稿）。

### 12.3 实机排障记录（2026-09-19，阶段 3 冒烟前三个启动崩溃，均已修复并实机验证）

1. **GBK 元数据**：`generateModMetadata` 缺 `filteringCharset='UTF-8'`，GBK 启动环境产出非法 UTF-8 的 `neoforge.mods.toml` → FML 扫描期 `MalformedInputException`。修复：显式字符集。
2. **mod 总线事件挂错总线**：`SincerelyMod.onCommonSetup(FMLCommonSetupEvent)` 带 `@SubscribeEvent` 被随 `NeoForge.EVENT_BUS.register(this)` 注册到 GAME 总线 → `IModBusEvent events are not allowed on the common NeoForge bus`。修复：删注解，仅走 `modEventBus.addListener`。`@EventBusSubscriber` 注解类由 NeoForge 自动按事件类型拆分总线，无需处理。
3. **命令树包截断**：`UnicodeWordArgument` 只调 `ArgumentTypeInfos.registerByClass`（仅填 BY_CLASS map），未注册进 `COMMAND_ARGUMENT_TYPE` registry → 进存档时命令树包序列化写 id=-1、客户端 `byId(-1)=null` 字节流错位 → `Failed to decode packet 'clientbound/minecraft:commands'`。修复：`DeferredRegister.create(BuiltInRegistries.COMMAND_ARGUMENT_TYPE, MOD_ID)` + supplier 内回填 BY_CLASS（计划 4.11 的「编译期核实」结论被实机推翻：编译通过 ≠ 网络序列化可用）。

修复后 runClient 验证：模组完整加载进主菜单 → quickPlay 进存档 `新的世界1` 成功（`Dev加入了游戏`，无 DecoderException），Mixin 零报错，TaskCompat 报告 supported=9 fallback=11，payload 协议 3 注册正常。
