# 自动工作模式（工作自切换）

## 功能概述

自动工作模式（面向用户："自动切换工作 / Auto Switch Work"）让女仆根据周围情况自动切换工作模式。每只女仆独立维护是否启用自动调度及所选预设；**预设库保存在玩家本机的客户端**，给女仆选预设时把当时的 id/name/order 烤成该女仆的**绑定快照**，服务端调度只读这份名单（详见 `docs/adr/0004-client-preset-library-and-maid-bound-snapshot.md`）。排序方式统一为纯列表顺序，索引 0 为最高优先级。

## 架构（客户端预设库 + 女仆绑定快照）

```text
AutoWorkClientLibrary（客户端本机 auto_work_presets.json v3，唯一写入方）
    │  打开该女仆配置页时：增删改序 / 选预设 / 新建 / 切换 < > 都发送 SetMaidAutoWorkPresetC2SPacket(id/name/order)
    ↓
AutoWorkPresetService（服务端冻结种子：每个 MinecraftServer 只读一次、不再写回）
    │  登录时 AutoWorkSeedS2CPacket 只拷给"空库"客户端；旧状态仅有 presetId 时按它烤快照
    ↓
AutoWorkStateService（每女仆 enabled + presetId/presetName/order/bound/revision，TLM TaskData 持久化）
    ↓
TaskDetectionScheduler -> MaidDetectionCache（读取女仆绑定 order）
    ↓
TaskSwitchDecisionEngine -> maid.setTask(realTask)
```

**核心设计**：自动工作模式不是 `IMaidTask`。`maid.getTask()` 始终为真实执行的工作（攻击、农耕等），自动调度状态独立存储，不随真实任务切换而丢失。

调度必须在服务端跑，但预设不必全服共享：服务端只使用女仆自己的绑定快照。打开某只女仆的配置页时，对该预设的增删改序会立刻写本地库并重新烤到这只女仆；没打开配置页的其他女仆、以及推送入库，都不会自动改已绑定快照。点 `<`/`>` 是换预设并烤到当前女仆。

## 检测器与缓存

`TaskWorkDetectorRegistry` 支持第三方附属注册专用检测器：

```java
TaskWorkDetectorRegistry.register(taskUid, detector);
TaskWorkDetectorRegistry.registerFallback(MyTaskInterface.class, detector);
```

UID 精确注册优先于接口或类型 fallback。重复 `register` 会记录 WARN 并拒绝覆盖；明确需要替换时使用 `replace` 或 `replaceFallback`。注册表还会保留解析来源（精确 / fallback / 无 Detector），供兼容预检使用。

检测结果为不可变的 `DetectionResult`：

```java
public record DetectionResult(
        ResourceLocation taskUid,
        Availability availability,
        long sampledTick,
        int ttlTicks,
        int consecutiveConfirmations,
        String evidence,
        BlockPos targetPos,
        UUID targetEntityUuid
) {}
```

结果过期、检测异常、任务未注册、预算耗尽或没有检测器都会产生 `UNKNOWN`。未知不等于可用：系统不会以 `IMaidTask.isEnable()` 作为通用兜底，避免将女仆切入没有真实目标的附属工作。

### 附属兼容边界

内置 fallback 仅覆盖语义标准的 `IAttackTask` 与 `IFarmTask`。任务具有私有目标选择、附属 Handler 或特殊状态机时必须注册 UID 专用 Detector。当前已核验的兼容矩阵：

- `touhou_little_maid:honey`：成熟蜂巢 POI、主手剪刀或玻璃瓶、产物空间与可达性；坐下/睡眠/拴绳等不可移动状态返回 `UNAVAILABLE`，骑乘（椅子/棋盘/船等）时仍参与扫描；
- `touhou_little_maid:feed`：主人状态与公开 `IFeedTask` 食物优先级，外部存储补货不在检测阶段触发；
- `touhou_little_maid:milk`：空桶、背包空间与可达的成年牛；
- `touhou_little_maid:feed_animal`：专用良性喂养检测，覆盖错误的 `IAttackTask` fallback，不把超量攻击动物作为自动工作；
- `touhou_little_maid:torch`：亮度、放置面、普通火把、Home/Owner 与路径预算；
- `touhou_little_maid:fishing`：主手或背包存在鱼竿、可见空椅子及水域；切入前自动换到主手，已有鱼钩时保持当前任务；
- `touhou_little_maid:extinguishing`：主手或背包存在灭火器，以及着火的主人、女仆或附近驯服动物；切入前自动换到主手。只灭生物身上的火，不处理地面火焰与着火敌对生物（与 TLM 原语义一致）；
- `touhou_little_maid:shears`：主手或背包存在剪刀与范围内可剪实体；切入前自动换到主手；
- `touhou_little_maid:board_games`：未占用、或正由本女仆使用的 `JOY_BLOCK` POI（自身 `sitId` 视为占用中的可用，避免下棋途中被判不可用而下车）；
- `maidsoulkitchen:berries_farm`：使用 MSK 公共 `ICompatFarmTask` Handler 链；可达性按 MSK 浆果脑的 3×2×3 包围盒判定（浆果丛本身是 `DAMAGE_OTHER`，单点查询恒不可达）；
- `maidsoulkitchen:fruit_farm`：使用每女仆 Handler 与 `searchYOffset` 扫描成熟水果；范围、主人距离与可达性都判在 `crop.below(searchYOffset)` 的**基准点**上（对齐 `MaidCompatFruitMoveTask`），不再错误地检查果实树叶方块；
- `maidsoulkitchen:feed_animal_t`：已完成专用 Detector，按同种动物分组、数量阈值、食物、年龄与路径执行繁殖/清理检测；
- `maidsoulkitchen:cook`：已完成炉灶子任务 Detector，仅支持女仆配置为 `maidsoulkitchen:furnace` 时的炉灶家族；其他设备返回不可用，不猜测私有规则。兼容报告中标记为部分支持（`PARTIAL_SUPPORT`），永久列入问题视图与进服提醒；
- `maid_useful_task:maid_tree`：已完成专用 Detector，只读复刻站立位上方树叶、自然树近似过滤与可达性，不调用会写 Brain 缓存的附属 DFS；
- `maid_useful_task:locate`：不适用自动切换，不注册 Detector。该任务要求非 home 模式、主人在 3 格内、主手持定位物，本质是跟随主人的寻路任务；兼容报告显示无检测器，永不自动切入；
- `maid_useful_task:revive_player`：不适用自动切换，不注册 Detector。该任务由玩家死亡事件驱动，无稳定世界扫描语义；兼容报告显示无检测器，永不自动切入；
- `maid_storage_manager:storage_manage`：支持明确的 PLACE/RESORT 待存状态，优先读取 active/bound/ViewedInventory 仓库，并按 MSM 的 ITEM_HANDLER 规则验证；REQUEST、CO_WORK 和未核验状态保持 `UNKNOWN`。实测基线为 MSM 1.15.6（1.4.1 的 `ChatBubbleMgrMixin` 与 TLM 1.5.3 不兼容，女仆一切入 PLACE 即崩服）。

`touhou_little_maid:idle` 是系统兜底而非工作目标，不注册普通 Detector，也不会被自动切入。兼容报告与四项统计计数中排除 `idle`（不再显示"不支持"），但其注册 UID 仍登记用于配置校验，`isAutoScheduleAllowed(idle)` 恒为 `false`。自动工作启用后，绑定快照外的未知当前任务可以被已确认可用的配置候选接管；快照内仍可调度但检测未知的当前任务只允许让位给更高优先级候选，已失效或被兼容策略排除的当前任务允许让位给任意确认候选。

### 静态兼容预检

服务器启动时会生成任务兼容报告：`SUPPORTED`（专用 Detector）、`FALLBACK`（接口通用检测）、`UNSUPPORTED`（没有可靠检测）和 `BLOCKED`（黑名单）。`UNSUPPORTED` 与 `BLOCKED` 不会自动切入；白名单仅消除提醒，不会绕过当前 generation 的 `AVAILABLE` 证据。报告顶部的"专用 / 通用回退 / 不支持 / 已阻止"四个计数均为可点击组件，点击直接打开对应分类的第 1 页。

配置文件为 `config/tlm_sincerely/auto_work_compat.json`，首次启动创建：

```json
{
  "version": 1,
  "blacklist": [],
  "whitelist": [],
  "knownBadFallback": [],
  "reminderLevel": "OP_ONLY"
}
```

可使用 `/tlmautowork compat report [page]` 查看默认问题视图（黑名单 + 未白名单的不支持任务）；`/tlmautowork compat report all [page]` 查看全部任务；`/tlmautowork compat supported|fallback|unsupported|blocked [page]` 查看对应分类。分类列表的上一页 / 下一页会携带当前筛选，点击顶部计数可直接跳到该分类第 1 页。查看报告无需管理员权限；`blacklist add/remove/list <uid>`、`whitelist add/remove/list <uid>`、`set reminder <ALL|OP_ONLY|DISABLED>` 与 `reload` 仍要求权限等级 2。任务 UID 参数支持 `namespace:path`。进服提醒与命令共用同一套本地化分页界面，提醒默认打开问题视图。

### 攻击检测

`AttackTaskWorkDetector` 对 `IAttackTask` / `IRangedAttackTask` 先校验武器，再按**主模组该攻击任务自己的反应范围**取候选目标：用 `IMaidTask.searchDimension(maid)` 划定搜索盒（近战默认是工作范围半径，弓兵是 `MaidConfig.BOW_RANGE`），逐个要求 `attackTask.canAttack(maid, target)`、视线可见，并通过与 TLM `farAway` 相同的距离判据——近战在跟随模式下按**主人到目标**的距离比较 `searchRadius`，弓兵按**女仆到目标**的距离比较 `searchRadius`。

不使用 `findFirstValidAttackTarget(maid)` 直接读 Brain 记忆：那份记忆是按女仆**当前**任务的扫描范围维护的，且 `maid.canAttack` 会把判定委托给当前任务，可能给出切过去之后 TLM 立刻丢弃、女仆原地发呆的假目标。普通模式下检测间隔为 10 tick；实验性攻击抢占打开时为 5 tick。决策引擎只消费检测缓存，不会重复查询攻击目标。

武器按任务家族区分，主手或背包持有即可；真正切入前由 `MaidHardToolService` 换到主手（弓兵只换弓，箭留在原处）：

| 任务 | 武器要求 |
|------|----------|
| `touhou_little_maid:attack`（近战） | 主手 `ATTACK_DAMAGE`，且排除弓、弩、三叉戟、御币 |
| `touhou_little_maid:ranged_attack`（弓兵） | 弓 + 任意可用箭（`getAllSupportedProjectiles`，手部或背包） |
| `touhou_little_maid:crossbow_attack` | 弩（不校验弹药） |
| `touhou_little_maid:trident_attack` | 三叉戟（不校验弹药） |
| `touhou_little_maid:danmaku_attack` | 御币（不校验弹药） |
| 第三方 `IAttackTask` | 保持其自身 `isWeapon(maid, stack)` 契约 |

近战攻击永不把远程武器当可用武器：TLM 的 `TaskAttack.isWeapon` 会把弓当作近战武器，因此本模组近战判定不复用它，而是显式排除弓/弩/三叉戟/御币。女仆身上只有弓时近战 `attack` 返回不可用。

### 农耕检测

`FarmTaskWorkDetector` 对 `IFarmTask` 执行增量环形扫描：

- 中心为 Home 限制中心或女仆当前位置。
- 扫描范围为女仆工作范围，垂直范围为 2。
- 候选必须满足 Home 限制，非 Home 时必须靠近 Owner。
- 使用种子副本调用 `canHarvest()` / `canPlant()`；没有种子时依然检查收获。
- 每个农耕检测器单次最多处理 64 个方块；全局受 `DetectionBlockBudgetPerTick` 与 `PathCheckBudgetPerTick` 限制。
- 扫描未完成时保存 `TaskScanCursor` 并返回 `UNKNOWN`，下个 tick 从当前位置继续。

可达性只在发现可收获或可种植候选后才检查，并且必须复刻该任务真实 AI 的判据（`FarmReach`）：

- **默认 `IFarmTask`**（`MaidFarmMoveTask`）：对 `basePos` 单点 `MaidPathFindingBFS.canPathReach`。
- **`touhou_little_maid:cocoa` / `melon`**（`MaidFarmSurroundingMoveTask`）：对 `basePos` 周围 `(-1,0,-1)..(1,1,1)` 的 3×2×3 任一格可达即可。第三方 `IFarmTask` 无法内省，保持单点语义。
- **禁止使用 `EntityMaid.canPathReach`**：其 A* 要求目标格本身是寻路节点，而浆果丛、可可、树叶的 malus 为 -1，永远不是节点，会导致整轮扫描恒 `FULL_SCAN_ALL_UNREACHABLE`。
- 每次扫描复用一个 `MaidPathFindingBFS` 并在结束时 `finish()`；路径预算耗尽时保留当前游标，下个 tick 重试该候选，避免整轮跳过。

## 决策规则

1. 只考虑当前绑定快照中存在、能通过 `isEnable(maid)` 的任务。
2. 按绑定 `order` 列表顺序排序，索引越小优先级越高。
3. 候选连续达到 `AvailableConfirmations` 次 `AVAILABLE` 后才能切入。
4. 当前任务连续达到 `UnavailableConfirmations` 次 `UNAVAILABLE` 后才能离开。
5. 当前任务为 `AVAILABLE` 时稳定保持；`MinimumTaskHoldTicks` 结束后可升级到更高优先级的 `AVAILABLE` 任务。
6. 全部结果为 `UNKNOWN` 或 `UNAVAILABLE` 时不切换。
7. **当前任务 UNKNOWN 接管语义**（v3 平衡策略）：
   - 绑定快照外的未知当前任务（非 idle）可被已确认可用的配置候选接管（`EXTERNAL_UNKNOWN_REPLACED`）；
   - 快照内仍可调度但检测未知的当前任务只允许让位给更高优先级候选（`HIGHER_PRIORITY_OVER_UNKNOWN`），更低候选则保持；
   - 已失效或被兼容策略排除的当前任务允许让位给任意已确认候选（`CURRENT_UNSUPPORTED_OR_DISABLED`）；
   - **保留**所有原有保护：AVAILABLE 优先级保护、UNAVAILABLE 确认次数、反向切换冷却、实验性攻击抢占不计入反向计数。
8. **工作中保持**：当前任务的 Brain 仍存在 `ATTACK_TARGET`、`WALK_TARGET`、`PATH` 或 `TARGET_POS` 时，普通切换暂缓；连续空闲、持续确认不可用或达到单段 busy 硬上限后放行。实验性攻击抢占不受此保护阻挡。
9. **硬性工具/武器**：fishing/shears/extinguishing 与攻击族（近战/弓/弩/三叉戟/御币）的 Detector 接受背包物品；真正切换前按 TLM 相同的整槽交换语义自动换到主手。检测后工具若已被移走，本次切换直接取消。
10. **骑乘仍扫描**：女仆处于骑乘（椅子、棋盘、船等）时，检测器仍对绑定顺序内全部任务做可用性扫描，不因骑乘跳过。
11. **调度下车**：自动切入的下一任务不是当前这份骑乘工作（钓鱼椅、棋盘等）时，`setTask` 前先 `stopRiding`；当前骑乘工作仍 `AVAILABLE` 则保持坐着。不改变玩家 `shift+右键` 的坐下待命。
12. **强制启用预选工作**：`ForceEnablePreselected`（默认关）仅让兼容黑名单（`CONFIG_BLACKLIST`）不再阻止自动切入；仍须 Detector 给出 `AVAILABLE`，idle、无检测器与 known-bad fallback 永不切入。

启用自动工作、选择/烤绑定快照（`SetMaidAutoWorkPresetC2SPacket`）、Agent 修改绑定顺序，以及运行时服务重建后的恢复，都会创建新的运行时 detection generation：旧 definitive 缓存和扫描游标立即失效，调度器优先 forceRescan。决策只消费当前 generation 的 fresh 结果，不等待同 tick 扫完全部任务。

普通切换会记录短窗口内的任务对反向切换。达到 `ReverseSwitchThreshold` 后，进入 `ReverseSwitchCooldownTicks` 的有限冷却；实验性攻击抢占不计入该计数。`ForceBrainRefreshOnStuck` 还要求当前 generation 的 `AVAILABLE` 结果带有可达目标位置或实体证据。

玩家手动选择普通工作模式时，GUI 会先发送 `SetMaidAutoWork(false)` 关闭自动调度，再由主模组执行任务切换。其他附属或命令修改真实任务时，自动状态保持不变，系统会给予短宽限期避免抢夺。

## 生命周期

`TaskDetectionRuntimeState` 以服务器实例隔离检测缓存、扫描游标和决策状态：

- `ServerStarting` 创建新会话状态，`AutoWorkPresetService` 和 `AutoWorkStateService` 绑定服务器实例。
- 玩家登录时发送冻结种子（`AutoWorkSeedS2CPacket`）与当前快照；客户端仅在空库时导入种子。
- `ServerStopped` 清空全部状态并解绑。
- 女仆死亡或离开 Level 时清理对应 UUID。
- 启用/切换预设产生的一次性立即评估请求也会在女仆离开、死亡、服务器启动/停止时清理。
- 若检测到 tick 回退，运行时状态重置。

这避免了集成服务器退出世界后将旧冷却或扫描时间戳带入新世界。

服务实例重建完成后，已启用且处于 `WORK` 的女仆会收到一次 `SERVER_REBIND` forceRescan；持久化的绑定快照保留，旧服务器实例的 generation、缓存和防抖状态不会复用。

## 预设库、绑定快照与界面

### 数据模型

- `AutoWorkPreset`：UUID、名称、纯 `List<ResourceLocation> order`（位置即优先级）。
- `AutoWorkClientLibrary`：**客户端私有库**，文件 `config/tlm_sincerely/auto_work_presets.json`（v3 格式：`version`、`defaultPreset`、`presets[id, name, order]`）；本类是本机文件唯一写入方。创建/改名/删除/增删任务/移动、首次进服导入种子、应用推送都在这里落盘。
- `AutoWorkPresetService`：**服务端冻结种子**。每个 `MinecraftServer` 生命周期内只读一次文件，之后不再读写；用途仅限"登录时拷给空库客户端"、"旧女仆仅有 presetId 时烤快照"以及尚未绑定女仆的默认预设回退。
- 旧格式：只有 v1/v2 而没有 v3 的文件视为空库（不迁移、不回写）；磁盘上遗留的 `.bak` 不读取。
- 单人游戏下客户端与服务端可能读到同一文件：客户端空库（没有文件且尚未编辑）才接受种子，已有库不覆盖。
- `AutoWorkState`：每女仆持久化的绑定快照，通过 TLM `TaskDataRegister` 存储。

Java 字段与 NBT 标签对应：

| Java 字段 | NBT 标签 | 含义 |
|-----------|----------|------|
| `enabled` | `enabled` | 该女仆是否启用自动调度 |
| `presetId` | `presetId` | 绑定预设 UUID |
| `presetName` | `presetName` | 快照时的预设显示名 |
| `order` | `order` | 快照时的任务 UID 列表 |
| `snapshotBaked` | `bound` | 是否已烤过快照（旧数据仅存 presetId 时为 false） |
| `revision` | `revision` | 每次变更自增，客户端缓存据此识别变化 |

### 网络协议（`PROTOCOL_VERSION = "3"`）

预设库编辑不再走网络。线格式只承载女仆绑定快照、兼容条目、登录种子与推送内容；协议版本在格式不兼容变化时递增。

| INDEX | 包 | 方向 | 作用 |
|-------|----|------|------|
| 0 | `AutoWorkSnapshotS2CPacket` | S2C | 女仆绑定状态（enabled/presetId/presetName/order/bound/revision）+ 兼容条目；**不再包含全库** |
| 1 | `RequestAutoWorkSnapshotC2SPacket` | C2S | 请求快照 |
| 2 | `SetMaidAutoWorkC2SPacket` | C2S | 启用/关闭指定女仆自动调度 |
| 3 | `SetMaidAutoWorkPresetC2SPacket` | C2S | 把整份 id/name/order 快照烤到指定女仆（同 UUID 再选即重新烤） |
| 10 | `OpenAutoWorkConfigC2SPacket` | C2S | 打开独立配置 GUI |
| 11 | `AutoWorkSeedS2CPacket` | S2C | 服务端冻结种子；登录发送，客户端仅在空库时导入 |
| 12 | `AutoWorkPushApplyS2CPacket` | S2C | 接收方已同意，写入其客户端预设库 |
| 13 | `AutoWorkPushOfferC2SPacket` | C2S | 发送方提交推送内容，服务端校验目标/权限后挂起等待确认 |

线格式上限：一次传输最多 64 条预设，每条预设最多 512 个任务；**编码端按与解码端相同的上限钳制，超出部分静默截断**（编码超限而解码抛异常会直接断开连接）。

已删除的旧共享库 C2S：`CreatePreset` / `RenamePreset` / `DeletePreset` / `AddPresetTask` / `RemovePresetTask` / `MovePresetTask`。

### GUI

- **底部开关**：女仆立绘下方 `AutoWorkVirtualTaskButton`（69×29），四态纹理取自 `maid_gui_sincerely.png`（v0 正常未开启 / v30 全局关闭未开启 / v60 正常开启 / v90 全局关闭开启），实际点击区域限于纹理内 (4,8) 起的 63×19，文字按点击区数学居中。无时钟图标、无蓝框、无状态色，统一黑色文字。
- **配置入口**：顶部水平 Tab 第 4 槽（`MaidTabs` Mixin `getTabs` RETURN），Tab 图标取自 `maid_gui_sincerely.png` (u=171, v=0, 16×16)，背景切片取自 `maid_gui_side.png`。
- **配置页面**：`AutoWorkConfigScreen extends AbstractMaidContainerGui`，面板背景从 `maid_gui_main.png` (80,28,176×137) 1:1 blit。预设行 `< > [名称 EditBox] × +`，双栏任务列表 5 行 × 73×16，条目纹理取自 `maid_gui_sincerely.png` (u=97, v=0)，选中态 (u=97, v=17)（悬停与点击选中均触发）。按钮纹理参数化：预设栏/任务行用 gui 纹理，控制按钮用 task 纹理，hover 偏移 v+14。预设名称 EditBox 防抖写入本地库（无需确认按钮）。预设份数以 `当前/总数` 格式显示。
- **本地库语义**：右列编辑的是本机当前预设。打开这只女仆的配置页时，增删任务、`↑`/`↓` 改序、改名都会立刻写入本地库并重新烤到这只女仆，没有单独的保存按钮。点 `<`/`>` 切换或 `+` 新建同样烤快照。未打开配置页的其他女仆、以及推送入库，都不会自动改已绑定快照。删除本地预设后，当前女仆改绑默认预设。
- **选中状态追踪**：右列任务选中状态以任务 UID（`ResourceLocation`）追踪而非列表索引，避免移动/重排后丢失选中。
- **手动接管**：`AbstractMaidContainerGuiMixin` 在 `taskButtonPressed` HEAD 注入先发送 `SetMaidAutoWork(false)`，确保玩家手动选择普通任务时自动退出自动模式。
- **兼容提示**：配置页任务行只显示任务名，不显示兼容悬浮。兼容等级通过进服提醒与 `/tlmautowork compat report` 查看。

### 预设推送

预设数据在发送方客户端，因此发送命令是**客户端命令**；服务端只做目标校验、权限检查与转发，接收方确认前不写任何库、不碰任何女仆。

| 命令 | 端 | 作用 |
|------|----|------|
| `/tlmautowork preset send <目标玩家名\|all> [预设名或UUID]` | 客户端 | 推送一条预设（省略参数时推当前默认预设） |
| `/tlmautowork preset sendlibrary <目标玩家名\|all>` | 客户端 | 推送整份本地预设库 |
| `/tlmautowork preset accept <token>` | 服务端 | 聊天按钮调用；同意并把预设写入本地库 |
| `/tlmautowork preset reject <token>` | 服务端 | 聊天按钮调用；拒绝 |

- `all` 需要权限等级 2，向除自己外的全服在线玩家广播；指定玩家使用在线玩家名。
- 报价 60 秒超时（常量，非配置项）。发送方会收到等待确认、成功、被拒绝或超时的回执。
- 接收方接受后经 `AutoWorkPushApplyS2CPacket` 写库：同 UUID 覆盖库条目；不同 UUID 撞名自动改名（`名称 (2)` 等）入库，不覆盖原预设。写库不改任何已绑定女仆。
- 服务端转发前会清洗 payload：剥离 `§`、丢弃空名、去重、剔除本服未注册的任务 UID，并截到 64 条上限。

### Jade 集成

`AutoWorkJadePlugin` 通过 `@WailaPlugin` 注册 `AutoWorkJadeProvider`，仅当 Jade 存在时加载。玉信息栏在**该女仆 `enabled` 且全局 `multi_task.Enabled` 开启**时，于「主人：」「模式：」同列追加一行「处于工作自动切换模式」；数据来自 TLM 同步到客户端的 TaskData，不需要额外网络包。

## 配置

```toml
[multi_task]
Enabled = true
PollInterval = 100
ExperimentalAttackPreempt = false
ForceEnablePreselected = false
DisableCompatReminder = false
ForceBrainRefreshOnStuck = true
AvailableConfirmations = 1
UnavailableConfirmations = 2
MinimumTaskHoldTicks = 60
ReverseSwitchWindowTicks = 240
ReverseSwitchThreshold = 2
ReverseSwitchCooldownTicks = 200
BusyGuardEnabled = true
BusyIdleForgiveTicks = 60
BusyUnavailableHoldTicks = 80
BusyGuardMaxTicks = 600
DetectionBlockBudgetPerTick = 256
PathCheckBudgetPerTick = 4
```

`Enabled` 是自动工作模式的全局开关，**默认开启**。关闭后 `TaskAutoSwitchHandler` 会在 server tick 入口直接 `return`，女仆不再参与自动调度；但是：

- 女仆当前真实任务（`maid.getTask()`）不会被清空或重置；
- 每女仆的绑定快照（enabled + presetId/order）不会被修改；
- 重新打开后调度从既有状态继续，无需重新建索引或清空预设。

`ForceEnablePreselected` 默认关闭。开启后兼容黑名单（`CONFIG_BLACKLIST`）不再阻止自动切入，但**检测器仍须给出 `AVAILABLE`**；idle、无检测器与 known-bad fallback 仍永不切入，兼容报告也仍把黑名单任务标为 `BLOCKED`。开启时玩家进服会额外收到一条金色警告。

`DisableCompatReminder` 默认关闭（即不关闭提醒）。开启后进服不再发送工作兼容问题摘要，`reminderLevel` 与 `DISABLED` 的差异只在关闭本开关时生效；手动 `/tlmautowork compat report` 不受影响，「强制启用预选工作」的金色警告也不受本开关影响。

配置键名沿用 `multi_task` 以保持向后兼容；面向用户的显示名统一为"自动工作模式 / Auto Work Mode"，界面入口为"自动切换工作 / Auto Switch Work"。GUI 中全局开关关闭时，底部按钮纹理自动切换到对应四态（未开启+全局关闭 / 已开启+全局关闭），文字统一黑色。

`ExperimentalAttackPreempt` 只控制立即攻击抢占，不控制攻击任务是否参与普通优先级排序。它仅在自动工作模式开启、绑定快照包含攻击任务且存在有效攻击目标时才生效，并在目标消失后恢复抢占前的可用任务。

`ForceBrainRefreshOnStuck` 默认开启。自动切换后，如果当前任务的独立检测结果仍为 `AVAILABLE`，但连续 60 tick 没有产生 `ATTACK_TARGET`、`WALK_TARGET`、`PATH` 或 `TARGET_POS`，系统会额外调用一次主模组 `refreshBrain()`，重建 Behavior 并重置其首次检查状态。每次自动切换最多触发一次；若与其他修改女仆 AI 的附属冲突，可关闭该项。

旧版 `AttackPreempt`、`ProbeGraceTicks`、`ProbeWaitTicks`、`ProbeCooldown` 已从 ForgeConfigSpec 中移除。新系统只使用独立的 `ExperimentalAttackPreempt`，且默认关闭；旧 `AttackPreempt=true` 不会迁移或开启实验性抢占。

## AI Tool

`AutoWorkTool`（`auto_work`）在服务端权威地查询与操作**当前女仆的绑定快照**：

| action | 作用 |
|--------|------|
| `query` | 查询全局开关、该女仆 enabled、绑定预设与完整绑定顺序（含每个任务的 Detector 等级与原因） |
| `set_auto_enabled` | 启用/关闭该女仆的自动调度 |
| `add_task` | 追加任务到该女仆的绑定顺序 |
| `remove_task` | 从绑定顺序移除任务 |
| `move_task` | 按 1-based 位置调整绑定顺序（越界钳制） |

预设库在客户端，服务端不可见：`select_preset` / `create_preset` / `rename_preset` / `delete_preset` 会被明确拒绝并提示改在女仆 GUI 操作；旧数字优先级 `set`（1-10）也被拒绝并提示改用 `add_task` / `remove_task` / `move_task`。修改绑定顺序或启用状态后会广播快照并请求一次立即评估。

`MaidAutoWorkContext` 会以自然语言追加全局调度状态、女仆自动工作状态、绑定预设、完整绑定顺序和兼容等级；不使用额外布尔字段表达上下文。配置界面任务行只显示任务名，兼容等级通过进服提醒与 `/tlmautowork compat report` 查看。

不再使用数字优先级（1-10），统一为纯列表位置。

## 手动验证重点

1. 当前农耕任务在 Brain Memory 间隙保持稳定，不在任务间横跳。
2. farm 无可用工作且 grass 可用时，只进行一次自然降级。
3. 高优先级任务出现后，在最短保持时间结束时升级。
4. 实验性攻击抢占关闭时，攻击遵守普通保持时间。
5. 实验性攻击抢占开启时，只有绑定快照中配置的攻击任务可立即抢占并在目标消失后恢复。
6. 退出并重新进入世界后，自动切换立即正常工作且无旧 tick 阻塞。
7. 顶部 Tab 打开独立配置页后，原攻击/农耕等任务配置 Tab 不受影响。
8. 底部开关四态纹理正确切换，点击仅在 63×19 区域生效，tooltip 仅悬停在该区域内显示。
9. 打开配置页时右列增删/改序/改名立刻写入本地库并烤到当前女仆；点 `<`/`>` 或新建同样烤入；未打开该页的其他女仆不受影响。
10. 首次进服且本机无预设文件时导入服务端种子；已有库（或已编辑）不被覆盖；v1/v2 旧文件被视为空库且不回写。
11. 推送：`accept` 写入接收方库、`reject`/超时只回执；同 UUID 覆盖条目，不同 UUID 撞名自动改名；`all` 需要权限等级 2；写入后不改接收方已绑定女仆。
12. 骑乘：钓鱼/下棋时仍对全部绑定任务扫描；切到非当前骑乘工作前先下车；当前骑乘工作保持坐着；玩家 `shift+右键` 坐下待命不受影响。
13. 近战女仆身上只有弓时 `attack` 不可用；弓兵需弓+箭；切入前工具/武器换到主手，检测后工具被移走则取消本次切换。
14. 开启 `ForceEnablePreselected` 后，黑名单任务在检测 `AVAILABLE` 时可切入；idle/无检测器仍不可；进服有额外金色警告。
15. 攻击范围：把敌人放在 `searchRadius` 之外（跟随模式下按主人距离算），攻击任务应保持不可用；目标进入范围后才切换，切入后女仆不会原地发呆。
16. 开启 `DisableCompatReminder` 后进服不再收到兼容摘要，但 `/tlmautowork compat report` 与强制启用金色警告仍正常。
17. 农耕可达性：站在成熟浆果/可可/水果旁时，evidence 不再固定为 `FULL_SCAN_ALL_UNREACHABLE`；可可与甜瓜按“周围任一格可达”成立，其余 `IFarmTask` 仍按基准点单点判定。
15. Jade 仅在该女仆启用且全局开关开启时显示「处于工作自动切换模式」。
16. 线格式钳制：本地库超 64 条预设或超 512 任务时静默截断，不因解码异常断开连接。
17. 专用服务器：客户端编辑本地库，服务端不写文件；推送只写入接收方客户端库。
18. 配置面板背景纹理 1:1 对齐，无白底闪烁。
19. 右列任务选中后点击"↑"/"↓"移动，选中高亮跟随同一任务不丢失。
20. EditBox 改名防抖写入本地库，输入中途收到 snapshot 不中断编辑。
21. 新建预设后份数显示立即更新，并把新预设烤到当前女仆。
22. 启用自动工作或选择预设后，日志出现 `immediate evaluation requested/completed`，且切换只基于明确可用任务。
23. 绑定快照包含无 Detector 的附属任务时，出现一次限流 `NO_DETECTOR` 提示，但任务不会被误判为可自动执行。
24. 多女仆农耕时检查 `FULL_SCAN_ALL_UNREACHABLE`、`PATH_BUDGET_EXHAUSTED` 与反向切换日志；稳定性优化按交接计划单独验收。
25. 重叠 UID 的绑定快照切换、Agent 修改绑定顺序和重新烤快照后，首个 `[TaskDecision]` 只使用新的 generation。
26. 多女仆、多农耕任务下检查 `[TaskBudget]`，确认不同女仆和同一女仆的不同 farm 任务均会获得扫描机会。
27. 登录后按 `reminderLevel` 收到兼容摘要；黑名单 fallback 任务绝不自动切入。
