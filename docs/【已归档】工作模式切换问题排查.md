# 工作模式切换问题排查

> 最后更新：2026-08-01
> 相关包：`priority/`、`priority/detection/`、`priority/decision/`

---

## 当前实现：独立工作检测

旧版 Probe 状态机已被替换。系统不再通过临时切换任务来判断任务是否有工作，也不再读取 Brain idle 状态作为可用性依据。

当前数据流：

```text
TaskPriorityPreset
  -> TaskWorkDetectorRegistry
  -> TaskDetectionScheduler（服务端主线程、分帧预算）
  -> MaidDetectionCache
  -> TaskSwitchDecisionEngine
  -> maid.setTask()
```

`TaskSwitchDecisionEngine.switchTo()` 是多工作模式中唯一的自动 `maid.setTask()` 调用点。

## 检测结果

| 结果 | 含义 | 决策行为 |
|------|------|----------|
| `AVAILABLE` | 已确认存在可执行工作 | 可作为候选任务 |
| `UNAVAILABLE` | 已完成扫描且确认无工作 | 当前任务连续达到阈值后可降级 |
| `UNKNOWN` | 无检测器、扫描未完成、预算耗尽、结果过期或检测异常 | 保守保持，不会触发盲目切换 |

未知附属任务固定返回 `UNKNOWN`。不会再被快速试切，也不会打断现有工作。

## 内置检测器

### 攻击任务

`AttackTaskWorkDetector` 支持 `IAttackTask`。它调用 `IAttackTask.findFirstValidAttackTarget(maid)`，并记录目标 UUID，不修改女仆的 Brain、导航或任务。决策与实验性抢占只读取缓存结果，检测周期为 5-10 tick。

### 农耕任务

`FarmTaskWorkDetector` 支持 `IFarmTask`，覆盖原生 farm、grass、sugar_cane 及使用同一接口的任务。

检测器会：

- 按 Home/Owner/工作范围规则扫描候选方块
- 使用 `canHarvest()` 与 `canPlant()` 做只读判断
- 在每轮扫描开始时复制种子快照
- 检查 `checkCropPosAbove()` 对应的上方空间
- 仅在发现可收获或可种植候选时调用 `maid.canPathReach()`
- 将扫描游标保存到缓存，受每 tick 方块与路径预算限制

检测器绝不调用 `harvest()`、`plant()`、`refreshBrain()`、`eraseMemory()` 或 `setTask()`。

## 决策规则

1. 仅处理当前预设中配置的任务，按优先级数字升序和同优先级手动顺序排列。
2. 候选必须 `isEnable(maid)` 且连续达到 `AvailableConfirmations` 次 `AVAILABLE`。
3. 当前任务连续达到 `UnavailableConfirmations` 次 `UNAVAILABLE` 后，才会降级。
4. 当前任务为 `AVAILABLE` 时保持稳定；最短保持时间结束后，才允许更高优先级的 `AVAILABLE` 任务升级。
5. 当前结果为 `UNKNOWN` 时保持任务，不执行快速横跳。
6. 无任何 `AVAILABLE` 任务时保持当前任务。

## 实验性攻击抢占

`ExperimentalAttackPreempt` 默认关闭。关闭时，攻击任务和其他任务一样按普通优先级与保持时间参与决策。

开启后，只有同时满足下列条件才会立即抢占：

- 多工作模式已启用，且女仆处于 `Activity.WORK`
- 当前预设已配置攻击任务
- 该任务可从 `TaskManager` 找到并实现 `IAttackTask`
- 该任务 `isEnable(maid)`，且 `findFirstValidAttackTarget()` 找到目标
- 当前任务不是同一攻击任务

攻击目标连续消失 20 tick 后，系统优先恢复抢占前仍为 `AVAILABLE` 的任务；否则按普通优先级选择可用任务。没有可用结果时保持当前任务。

## 生命周期安全

运行时状态以 `MinecraftServer` 实例隔离，在 `ServerStarting` 创建、`ServerStopped` 清除；女仆死亡或卸载时也会清理对应 UUID。若检测到服务器 tick 回退，状态会整体重置，避免集成服务器重进世界时旧时间戳阻塞新会话。

## 旧 Probe 配置

以下旧 Forge 配置字段已从代码与配置界面中移除：

- `AttackPreempt`
- `ProbeGraceTicks`
- `ProbeWaitTicks`
- `ProbeCooldown`

Forge 在下一次加载配置时会按新配置结构修正 TOML。旧 `AttackPreempt=true` 不会自动开启实验性抢占；新功能只读取 `ExperimentalAttackPreempt`，默认 `false`。

## 排查步骤

1. 确认 `Enabled = true`，并确认当前女仆日程为工作状态。
2. 确认活跃预设实际包含目标任务；未配置的任务不会参与检测或抢占。
3. 在 DEBUG 日志中检查 `[TaskDetect]` 的 `AVAILABLE`、`UNAVAILABLE`、`UNKNOWN` 结果及 evidence。
4. 检查 `AvailableConfirmations`、`UnavailableConfirmations`、`MinimumTaskHoldTicks` 与 `PollInterval` 是否符合预期。
5. 农耕任务检查作物/种子/Owner 或 Home 范围/可达性；无检测器的附属任务需要通过 `TaskWorkDetectorRegistry` 注册专用检测器。
6. 首次游戏内验证时确认 `maid.canPathReach()` 没有改变当前导航目标；若发现副作用，应将对应任务降级为 `UNKNOWN`，而不是牺牲当前任务稳定性。
7. 若 `[TaskStartup]` 在自动切换后持续 60 tick 全为 0，同时 Detector 仍为 `AVAILABLE`，确认 `ForceBrainRefreshOnStuck = true`；正常情况下日志随后会出现 `action=FORCE_BRAIN_REFRESH`，且每次自动切换最多执行一次。
