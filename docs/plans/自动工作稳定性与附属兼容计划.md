> 状态：待实施（交接计划）
>
> 编写日期：2026-08-10
>
> 项目：《车万女仆：真心为你》
> Mod ID：`tlm_sincerely`
> 目标平台：Forge 1.20.1 / Java 17
> 主模组依赖：Touhou Little Maid 1.5.3-forge
> 计划性质：基于实机 DEBUG 日志的自动工作稳定性与附属任务专用兼容实施计划

---

## 1. 目标与边界

本计划处理自动工作模式在实机运行中暴露出的三类问题：

1. 常规任务、手动/附属任务与自动任务切换时的交接稳定性；
2. 农耕任务的目标扫描、路径可达性与预算饥饿；
3. 已安装附属注册的 `IMaidTask` 缺少工作可用性检测器，导致可配置但无法自动切入。

### 1.1 必须达成

- 自动切换只在目标任务具有明确 `AVAILABLE` 证据时执行；
- 切换预设或启用自动工作时，先完成对应任务集的新鲜检测，再进行一次立即评估；
- 未实现专用 Detector 的附属任务不会被误判为“总是可用”，也不会被自动切入；
- 为日志已确认的高优先级任务补充专用 Detector 或明确标注为“暂不支持自动调度”；
- 减少 `UNKNOWN`、`FULL_SCAN_ALL_UNREACHABLE`、预算耗尽造成的无效循环与切换抖动；
- 保持服务端权威、每女仆独立状态、真实 `maid.getTask()` 语义和手动任务保护。

### 1.2 明确不做

- 不以 `IMaidTask.isEnable(maid)` 作为通用“有工作”判断；它只表示任务可使用，不能表示环境中有目标。
- 不让未知附属任务自动切入；否则会把女仆切到无目标的工作模式。
- 不在检测阶段调用 `maid.setTask()`、`refreshBrain()`、清 Brain Memory 或修改世界。
- 不修改已完成的 `自动切换工作模式v2计划.md` 与 `独立工作检测系统重构计划.md`。

## 2. 当前实现基线

```text
AutoWorkState(enabled + presetId)
        ↓
AutoWorkPreset(order)
        ↓
TaskDetectionScheduler ──> MaidDetectionCache
        ↓
TaskSwitchDecisionEngine.switchTo(...)
        ↓
AutoWorkInternalSetTaskGuard.runInternal(maid.setTask)
        ↓
TLM EntityMaid.setTask() -> refreshBrain(ServerLevel)
```

### 2.1 已确认正确的交接契约

- `TaskSwitchDecisionEngine.switchTo()` 是自动调度唯一调用 `maid.setTask()` 的位置；
- 网络包、GUI、Agent Tool 只修改自动状态/预设，并请求调度器评估，不直接切真实任务；
- TLM `EntityMaid.setTask(IMaidTask)` 在服务端会调用 `refreshBrain()`；
- `AutoWorkInternalSetTaskGuard` 标记内部切换，外部 `setTask()` 不会直接清空自动工作状态；
- `EXTERNAL_UNKNOWN_CURRENT` 会保留未知的当前真实任务，防止自动系统抢走附属或代码手动设置的工作。

### 2.2 当前立即评估的限制

`TaskAutoSwitchHandler.requestImmediateEvaluation()` 已能绕过 `PollInterval`，但不会强制新预设所有任务立即重扫。因此切换预设时可能消费旧缓存，必须在本计划第一阶段修正为“失效旧缓存 → 完成首轮检测 → 评估”。

## 4. 阶段 A：检测与交接稳定性

### A1. 预设变更的检测世代与立即首轮扫描

**问题**：立即评估会绕过轮询，但可能使用旧预设遗留的缓存结果。

**实现**：

1. 在 `TaskDetectionRuntimeState` 为每只女仆增加检测世代（或预设签名）；
2. `requestImmediateEvaluation` 改为保存 `reason` 与 `forceRescan` 标记；
3. 启用自动工作、切换预设、创建并绑定新预设时，标记该女仆当前预设任务缓存失效；
4. `TaskDetectionScheduler` 在同一服务端 Tick 优先为 `forceRescan` 女仆创建任务；
5. 仅当首轮产生对应预设的 definitive `AVAILABLE` / `UNAVAILABLE` 结果，或确认全部任务暂时 `UNKNOWN` 后，才调用决策引擎；
6. 日志增加 `generation`、`presetId`、`reason`、`freshTaskCount` 与 `staleTaskCount`。

**验收**：切换到含攻击/农耕任务的新预设后，首条 `TaskDecision` 的每个候选结果均属于该预设世代，不引用旧预设缓存。

### A2. 预算公平性与扫描完成度

**问题**：全局 `DetectionBlockBudgetPerTick=256`、`PathCheckBudgetPerTick=4`，多个女仆/农耕任务时会使扫描游标长期停留在 `UNKNOWN`。

**实现**：

1. 输出每 tick 的女仆数、任务数、块预算、路径预算、预算耗尽数；
2. 按女仆轮转分配预算，避免首个女仆持续吃光路径检查；
3. 为 `TaskScanCursor` 记录完整扫描周期数与连续预算耗尽次数；
4. 连续超过阈值时，降低该任务本轮优先级并让出预算，而不是每 tick 返回同一种 `UNKNOWN`；
5. 评估默认预算是否提高；先通过基准日志确定目标值，不直接盲目增大；
6. 区分 `FULL_SCAN_EMPTY`、`FULL_SCAN_ALL_UNREACHABLE`、`BLOCK_BUDGET_EXHAUSTED`、`PATH_BUDGET_EXHAUSTED`，不将它们混为单一不可用状态。

**验收**：两只以上女仆同时使用四个农耕任务时，每个任务都能在有限 tick 内完成至少一轮扫描；日志不再长期由 `BLOCK_BUDGET_EXHAUSTED` 主导。

### A3. 防抖与真实工作验证

**问题**：日志出现 `attack ↔ grass`、`danmaku_attack ↔ compat_melon` 周期性来回切换。

**实现**：

1. 在 `MaidSwitchState` 记录上一个任务、切换理由、切换目标位置与连续反向切换次数；
2. 当同一任务对在短窗口内反向切换达到阈值时，进入有限的反抖冷却，并输出 WARN；
3. 仅对“当前任务明确 `UNAVAILABLE`”或“更高优先级明确 `AVAILABLE`”适用，绝不因 `UNKNOWN` 强制切换；
4. `TaskStartup` 日志补充切换前后 UID、presetId、任务排名、检测证据、目标位置与 Brain Memory mask；
5. 保留现有 `ForceBrainRefreshOnStuck`，但在强制刷新前记录任务检测世代与最近可达目标，避免把扫描不足误诊为 Brain 卡死。

**验收**：连续攻击目标出现/消失时，切换次数不超过配置的保持时间允许范围；不会出现同一对任务每 60 tick 无限往返。

## 5. 阶段 B：专用 Detector 兼容层

### B1. 兼容层结构

新增 `priority/detection/compat/`，每个 Detector 独立文件，不在通用检测器中加入附属反射逻辑：

```text
compat/
  BuiltinShearsDetector.java
  MaidUsefulTreeDetector.java
  MaidSoulKitchenBerryDetector.java
  MaidStorageManagerDetector.java
  BoardGamesDetector.java                 # 仅在可定义可靠条件后实现
  CompatDetectorBootstrap.java
```

注册必须满足：

- 只在对应 Mod 已加载时注册；
- UID 注册优先于 `IAttackTask` / `IFarmTask` fallback；
- 缺少目标 Mod 的类时不得 ClassLoad；
- Detector 仅读取实体、方块、背包和公开 API；
- 返回 `AVAILABLE` 时必须给出 evidence 和目标位置/实体 UUID；
- API 无法可靠判断时保守返回 `UNKNOWN` 或 `UNAVAILABLE`，不得猜测可用。

### B2. 任务实施顺序

| 优先级 | Detector | 预研要求 | `AVAILABLE` 条件 | 备注 |
|---|---|---|---|---|
| P0 | `MaidUsefulTreeDetector` | 核验 `MaidTreeTask` 的公开过滤、范围、原木标签 | 范围内存在任务认可且可达的原木 | 不能仅见到任意日志就判定可砍 |
| P0 | `MaidSoulKitchenBerryDetector` | 核验 `ICompatFarmTask`、目标方块表、收获规则 | 存在可收获且可达的浆果/果树目标 | 不直接依赖 MSK 私有类；优先公开 API |
| P1 | `BuiltinShearsDetector` | 核验 TLM 剪毛任务对目标羊、冷却、羊毛状态和范围的规则 | 存在可剪且可达的羊 | 返回目标羊 UUID |
| P1 | `MaidStorageManagerDetector` | 核验 Storage Manager 公开能力/仓库标记/待整理条件 | 附近可访问仓储确有待整理项 | 若没有稳定公开 API，先保持不支持 |
| P2 | `BoardGamesDetector` | 明确玩家、棋盘、距离、背包等完整发起条件 | 所有交互前置条件均满足 | 未能可靠定义前，不注册 Detector |
| P2 | `FeedAnimalDetector` | 核验 TLM/MSK 喂动物语义 | 存在可喂动物且背包有有效食物 | 覆盖错误的 `IAttackTask` fallback |

### B3. UI、Tool 与 Context 提示

1. GUI 可用任务列表中，对无 Detector 的任务显示“不可自动检测”状态/Tooltip；
2. Agent `auto_work.query` 的任务条目附带检测器状态；
3. `MaidAutoWorkContext` 用文字说明当前预设包含的未检测任务；
4. WARN 使用每任务、每女仆、每个冷却窗口限流，避免日志刷屏；
5. 预设保存时做一次静态检测器覆盖检查，给出一次明确提示。

**验收**：用户在预设中加入 `maid_tree` 或 `berries_farm` 时，若兼容已实现则能拿到正确目标证据并切换；若未实现则 GUI/Tool/日志均明确说明原因。

## 6. 阶段 C：交接与生命周期回归

### C1. 常规/手动任务交接

- 手动点击 TLM 原始工作按钮：先发 `SetMaidAutoWork(false)`，随后真实任务切换；
- 附属或命令外部 `setTask()`：自动状态保持，但未知当前任务不会被立即抢走；
- 重新启用自动工作：触发本计划 A1 的新鲜检测，不直接以旧任务缓存切换；
- 预设删除后：回退默认预设并令受影响女仆重新检测。

### C2. `/reload` 与集成服务器

1. 重现 `/reload` 前后 `AutoWorkStateService` / `AutoWorkPresetService` 解绑与重绑；
2. 验证每女仆 TaskData 中的 `enabled + presetId` 是否完整保留；
3. 若运行时缓存重建后没有首轮调度，为已启用且处于 `WORK` 的女仆补一次有节流的重扫请求；
4. 禁止沿用旧服务器实例的 tick、扫描 cursor 与 `MaidSwitchState`；
5. 记录 `SERVER_REBIND`、恢复女仆数、预设数与首轮检测完成数。

## 7. 诊断日志规范

统一前缀并保留女仆 UUID、preset UUID、task UID：

| 前缀 | 必须字段 |
|---|---|
| `[TaskDetect]` | maid、preset、generation、task、availability、evidence、cursor、blocks/path budget |
| `[TaskDecision]` | maid、preset、current/selected UID、排名、reason、cache generation |
| `[TaskHandoff]` | maid、from/to、reason、Brain mask、目标位置/实体 |
| `[TaskCompat]` | mod、task、detector、注册成功/跳过原因 |
| `[TaskStability]` | maid、任务对、反向次数、冷却结束 tick |

DEBUG 用于逐 tick 数据；WARN 仅用于配置了但没有 Detector、持续预算饥饿、反复切换和生命周期恢复失败，且必须限流。

## 8. 验收矩阵

| 场景 | 期望结果 |
|---|---|
| 手动普通任务 → 自动工作 | 先完成新鲜检测；只切入明确可用任务 |
| 自动工作 → 手动普通/附属任务 | 自动状态关闭或未知任务受保护；不立即抢回 |
| 攻击目标出现/消失 | 遵守保持时间，不在攻击/农耕间短周期抖动 |
| 多女仆、多农耕任务 | 每只女仆获得公平扫描与路径预算 |
| 不可达作物 | 有 `ALL_UNREACHABLE` 证据，不反复误切入 |
| `maid_tree` | 专用 Detector 仅在有效、可达树木存在时切入 |
| `berries_farm` | 专用 Detector 与 MSK 真实收获规则一致 |
| 无 Detector 的任务 | GUI/Tool/Context 提示；日志限流；不自动切入 |
| `/reload` | 状态与预设保留；运行时缓存新建；已启用女仆恢复调度 |
| 专用服务器 | C2S/S2C 与 Agent 操作保持服务端权威 |
